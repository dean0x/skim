# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Skim** is a streaming code reader for AI agents, written in Rust on tree-sitter. It strips implementation detail while preserving structure, signatures, and types to optimize code for LLM context windows. It also compresses other agent context: test output, build errors, lint output, git diffs, logs, and raw shell commands.

**Key principle:** Skim is a *streaming reader* (`cat` but smart), not a file compressor. Output always goes to stdout for pipe workflows — never write intermediate files.

User-facing install/usage lives in `README.md`; release mechanics in `CHANGELOG.md`. This file is for working *in* the repo.

## Workspace

Cargo workspace, 10 crates:
- `rskim-core` — pure transform library (parsing, modes; no I/O side effects)
- `rskim` — CLI binary (`skim`): caching, analytics, command wrappers
- `rskim-proxy` — HTTP reverse proxy foundation for Layer-3 LLM request routing (hyper + tokio; isolated from default builds)
- `rskim-search` — code-search index (lexical n-gram, temporal, AST structural). All artifacts live under the OS cache dir, NOT the project root: base = `$SKIM_CACHE_DIR` if set, else the platform cache dir (`~/Library/Caches/skim` on macOS, `~/.cache/skim` on Linux), with the per-root subpath `search/<sha256(canonical_root)[..16]>/`. That dir holds the SQLite temporal DB (`temporal.db`) plus the lexical/AST index artifacts (`index.skidx`, `index.skpost`, `index.skfiles`, `ast_index.*`). Structural size inconsistency between an index header and its body file also triggers an automatic rebuild on the next query — no manual `--rebuild` needed (#414).
- `rskim-research` — offline tooling that generates both AST structural weight tables
  AND the lexical trigram IDF weight table (see codegen notes below)
- `rskim-bench` — benchmarks
- `rskim-tokens` — offline + optional-network token counting (multi-provider; `net-anthropic` feature gates HTTP)
- `rskim-contract` — byte-faithful contract / guardrail layer for transcript mutation
- `rskim-llm` — LLM transcript parsing (OpenAI/Anthropic) + classifier
- `rskim-compress` — per-content-type block compression router for the Layer-3 proxy (BlockRouter, log compression)

`crates/rskim-search/src/ast_weights.rs` is **auto-generated — do not edit**. Regenerate via `rskim-research ast-run` then `ast-codegen`.

`crates/rskim-search/src/weights.rs` is **auto-generated — do not edit**. It contains the lexical trigram IDF weight table (`TRIGRAM_WEIGHTS`, `lookup_weight`, `trigram_weight`). Regenerate via `rskim-research trigram-run` then `trigram-codegen`. The old `rskim-research codegen` subcommand (bigram-based) now writes to a separate `bigram_weights_legacy.rs` artifact and must NOT be used for the live trigram table.

## Architecture

```
Parser Manager (language detection)
  ↓
Language::transform_source()          ← Strategy Pattern dispatcher
  ├─ tree-sitter  (15 code langs: TS/JS/Python/Rust/Go/Java/C/C++/C#/Ruby/SQL/Kotlin/Swift/Bash/Markdown)
  └─ serde-based  (JSON/YAML/TOML — data formats, not code)
  ↓
Transformation Layer (modes: structure / signatures / types / minimal / pseudo / full)
  ↓
Streaming output (stdout, zero-copy via &str slices where possible)
```

`transform_source()` routes each language to its parser via the Strategy Pattern, avoiding special-case conditionals — each language encapsulates its own strategy.

**Non-obvious behavior (gotchas):**
- **Analytics:** token savings persist to `<cache-root>/analytics.db` (SQLite/WAL; default location — relocates with `SKIM_CACHE_DIR`, see Environment Variables), recorded fire-and-forget on background threads. The cache root is resolved by `cache.rs::cache_root_from`, which is an override-or-fallback: a usable `SKIM_CACHE_DIR` **is** the root and is used verbatim (no `skim` suffix appended), and only when none is given does it fall back to the `or_else` arm `dirs::cache_dir().join("skim")` — which is **platform-dependent**: `~/Library/Caches/skim/` on macOS, `~/.cache/skim/` on Linux. `~/.cache/skim` does not exist on a macOS dev box — read the real paths off `skim doctor` rather than assuming the XDG one, and do not describe the platform path as "the cache root" when an override is in play. `--clear-cache` clears only the parser cache, NOT `analytics.db` — use `skim stats --clear` for that. The `AnalyticsStore` trait + `MockStore` make the stats dashboard testable without a real DB. **Analytics schema migrations are two non-interchangeable idioms, and `PRAGMA user_version` governs only one of them** — `run_migrations` calls `run_versioned_migrations` (a forward-only LADDER: each rung gated on `user_version` and stamping the next number, currently topping out at 3) and then `reconcile_additive_columns` (a PRESENCE RECONCILE). The delivered-cost columns (`DELIVERED_COST_COLUMNS` = `notice_tokens`, `notice_bytes`, `served`) are added by presence-gated `ALTER`s that **stamp no `user_version` at all** — deliberately, because three lineages want a number against the same `analytics.db` and a stamp here would make another lineage's version-gated migration skip itself, fail every INSERT, and die silently in `persist_record`'s discard. **A new nullable column goes in the reconcile, not on the ladder.** This is the OPPOSITE model from `temporal.db` below (forward-only-and-refuse-newer) — do not read that paragraph's `PRAGMA user_version` prose as describing analytics. Nothing downstream consults the version anyway: `query_summary` selects the delivered series row-by-row on `notice_tokens IS NOT NULL`. **Presence-gating survives a foreign `ALTER`; it does NOT survive a foreign table REBUILD**, which silently drops the columns and every measurement in them (hence the `analytics_meta` marks, which live outside `token_savings` where a rebuild cannot reach them). Not hypothetical: the live DB measured at `user_version = 5` already carries both other lineages' tables, `proxy_block_decisions` and `alignment_decisions`, and its `token_savings` is already a post-rebuild reconstruction. **Read the `HAZARD FOR WHOEVER RECONCILES THESE LINEAGES` banner in `analytics/schema.rs` before merging or reconciling with another lineage** — it also documents the `user_version = 4` orphan an earlier commit of this branch created, how to identify one, and its one-line remedy.
- **Search DB:** `rskim-search` stores hotspot/risk/co-change data in the SQLite file `temporal.db`, located in the per-root search cache dir (`<cache_base>/search/<sha256(canonical_root)[..16]>/` — see the `rskim-search` crate note above for `<cache_base>`), NOT under the project root. Migrations on `temporal.db` are forward-only via `PRAGMA user_version`. SQLite-level corruption (SQLITE_CORRUPT / SQLITE_NOTADB) is a *discard-and-rebuild*: the file is deleted and one rebuild attempt follows; a DB written by a newer binary (higher `PRAGMA user_version`) is a *refuse*: it is never modified, skim exits 0 with a typed degraded notice and `temporal_state: "newer-schema"` in `--stats --json`; the remedy is to upgrade skim (`--rebuild` explicitly does NOT overwrite a newer-schema DB — the T-15 acceptance test deletes `temporal.db` by hand before calling `--rebuild` so the explicit rebuild creates a fresh schema-2 DB; the backoff sentinel, if written, is cleared automatically by `BuildLoudness::Loud` — AD-414-16) (AD-414-2, AD-414-11). `sync()` also records `is_shallow` in the `meta` key/value table (no schema bump); `temporal_db_is_stale` Check 3 detects the shallow→full transition (stored `is_shallow=1` plus `.git/shallow` now absent) and triggers a full rebuild automatically — no manual `--rebuild` needed (AD-414-14, OD-D). A separate `data_version` meta row (`TEMPORAL_DATA_VERSION = 2`, written unconditionally by `sync()`) also triggers an automatic full rebuild on the next query when absent or numerically stale — no manual `--rebuild` needed (AD-408-4, staleness.rs Check 2). A per-HEAD backoff sentinel file `temporal.db.build_backoff` is written to the same cache dir when a temporal build fails for a given HEAD commit, to bound quiet-path retries; it stores `<HEAD SHA>\n<shallow>` where `<shallow>` is `1`, `0`, or `?` (unknown) so the gate re-opens automatically after `git fetch --unshallow` (AD-414-21). `BuildLoudness::Silent` (the automatic quiet refresh path) respects the sentinel; `BuildLoudness::Loud` (explicit `--rebuild`/`--build`/`--update`) clears this sentinel at the start of the temporal rebuild (before the backoff gate) so an explicit rebuild always proceeds (F1 / AD-414-16). `--build` and `--rebuild` reach the clear unconditionally; `--update` reaches it only when `auto_refresh_if_stale` decides a rebuild is warranted. (The only `.skim`-named artifact in the search path is the advisory build lock `.skim-build.lock`, which also lives inside that cache dir — never in the project root.) **Linked worktree / subdirectory root behaviour (#413):** for a `git worktree add` linked worktree, HEAD is now resolved via the `commondir` pointer to the shared repository; for `--root <subdirectory-of-a-repo>`, the nearest **enclosing** repository (bounded ancestor walk, first match) supplies HEAD and history, while the temporal rows are **scoped** and re-anchored to the indexed subtree at build time — so one `--root` is one result universe on the temporal arms exactly as it already was on the lexical arm: every temporal arm (`--hot`/`--cold`/`--risky`/`--blast-radius`, compound `text --hot`, `--ast <pat> --hot`) returns only paths inside the subtree, and co-change peers outside it are dropped rather than shown. Pass the repository toplevel as `--root` for repository-wide ranking. A root that has its own `.git` is never re-pointed at an ancestor (`mkdir .git` stays `not_a_repo`). The repository that produced the rows is recorded in `temporal.db`'s `meta` as `git_toplevel`; if the enclosing repository later changes, skim **refuses** (serves no temporal ranking, rebuilds nothing, leaves `temporal.db` byte-unchanged, exit 0) rather than silently rescoring one repository's index with another's history — only `--build`/`--rebuild`/`--update` may re-anchor, and they disclose the old and new toplevel on stderr.  Both cases populate `temporal.db` and expose the `git_head_state` key in `--stats --json` (`"resolved"` / `"unresolved"` / `"not_a_repo"`).  **No-commit repositories (AD-414-22):** an unborn HEAD (`git init` with files but nothing committed) is an *empty history*, not a failure — `--build`/`--rebuild`/`--update` write a present-but-empty `temporal.db` that deliberately records **no** `git_head`, and print one stderr line naming the empty history (which does not mention "shallow" on a non-shallow repository); plain queries stay silent and build nothing, and the first query after the repository's first commit rebuilds automatically because the absent `git_head` reads as stale.  First upgrade from a pre-#413 build triggers a one-time automatic rebuild of `temporal.db` for roots that were previously unresolvable — expect one slow query, then normal performance.  `--install-hooks`/`--remove-hooks` in a linked worktree now routes to the shared `<commondir>/hooks` directory (the same directory `git rev-parse --git-path hooks` names) and discloses the clone-wide scope on stderr.  **Full-DAG temporal walk (#407):** the temporal layer now walks the **full commit DAG** and skips merge commits before the tree diff, matching `git log --no-merges` and skim heatmap's population; first-parent-only traversal is gone.  The first query after upgrading from a pre-#407 binary costs one slow rebuild per root (the `data_version` self-heal, AD-407-5, TEMPORAL_DATA_VERSION bumped 1 → 2); subsequent queries are fast until HEAD advances — the first query after each new commit re-walks history (if a previous walk failed for the current HEAD, the retry backoff defers the rebuild until HEAD advances or you run an explicit `skim search --rebuild`).  As a consequence of the full-DAG population, `--blast-radius` peer sets and ordering may differ from pre-#407 databases (AD-407-9).
- **Lexical n-gram index:** `index.skidx` / `index.skpost` is format v7 (trigram, u32 key from #355 Part B + delta+varint variable-length posting codec from #358 Item 2 + `token_position` from #392 + `token_length` from #411). This is DISTINCT from the AST structural index. Indexes at v2 (bigram, u16 key), v3 (trigram, u32 key, fixed 9-byte postings), v4 (variable posting codec), v5 (added token_position), and v6 (context-aware field_id classifier) all trigger an automatic rebuild on the next query via `check_staleness` — no manual `--rebuild` needed for any version upgrade. Short queries (< 3 bytes, e.g. `fn`, `if`) cannot produce trigrams and fall back to an all-files score-0 candidate set, which is filtered down to matching files by the Part A substring-verify gate (AD-355-7); this is correct behavior, not a bug. AD-372-4: `short_query_fallback` returns the **full** filtered candidate set with NO internal `.skip/.take` — offset+limit are applied by the caller AFTER verification (the only truncation gate). AD-411-7: `search_exact_intersection` filters candidates by `token_length == query_word_byte_len` to reject postings whose document token merely CONTAINS the query as a substring of a longer identifier (e.g. `test_check_staleness_present` must not match the query `check_staleness`). Structural size inconsistency between `index.skidx` and `index.skpost` (e.g. truncated body file) also triggers an automatic rebuild on the next query via `check_staleness` — no manual `--rebuild` needed (#414).
- **AST index:** the structural n-gram index (`ast_index.skidx` / `.skpost`) is format v3 (#405, bumped from v2) — v1/v2 files trigger an automatic rebuild on the next query via `check_staleness`. The per-file extraction cache (`ast_index.skcache`) is `CACHE_FORMAT_VERSION` 2 (#405, bumped from 1); v1 entries are silently discarded and re-extracted at up to 1 MiB. The per-file AST size cap is 1 MiB (raised from 100 KiB in #405); data formats (JSON/YAML/TOML) are never AST-indexed (they use a serde path). Synthetic n-gram markers (IDs ≥ 64900) resolve to `None` in `vocab_resolve()`, keeping them isolated from real vocabulary. `ast_coverage_notice` fires on `--build/--rebuild/--update/--ast/--stats` when excluded files exist (D-4 cadence); `--ast --json` includes an `ast_coverage` key when non-clean. Structural size inconsistency between `ast_index.skidx` and `ast_index.skpost` also triggers an automatic rebuild on the next query via `check_staleness` — no manual `--rebuild` needed (#414).
- **Search quality gate (ADR-007):** changes to retrieval ranking — BM25F config, field attribution, TF counting, scoring weights — require an adversarial dog-food pass against ground truth (git grep, ripgrep, raw file bytes) before promotion to main. A fully green CI and acceptance suite is not evidence of retrieval correctness; the dog-food campaign is the real merge gate for search-quality changes.

## Commands

To test changes in **this** clone, invoke its own build by path — `./target/release/skim` (refresh with `cargo build --release`). ⚠️ A bare `skim` on `$PATH` may resolve to a *different* local clone (this machine keeps parallel clones to avoid worktree churn), so it can silently exercise the wrong code.

```bash
cargo build --release          # production build
cargo test --all-features      # full test suite
cargo clippy -- -D warnings    # lint (warnings are errors)
cargo fmt -- --check           # format check
cargo bench                    # criterion benchmarks
cargo run --bin skim -- file.ts --mode=signatures   # run locally
```

`rskim` is bin-only (the `skim` binary; no `src/lib.rs`) — scope its tests with `cargo test -p rskim --bins` (or `--all-targets`). `cargo test -p rskim --lib` errors with "no library targets found" (a cargo target-selection behavior, not a skim bug). `rskim-core`/`rskim-search` are libraries and accept `--lib`.

### Build/test resource limits

A machine-global `~/.cargo/config.toml` caps every cargo invocation at `jobs = 4` and `RUST_TEST_THREADS = 4`, and routes compilation through `sccache` (a compile cache shared across parallel clones). **That config file is the enforcement layer — it protects every branch and clone regardless of this doc; the guidance below exists because the cap alone can still be multiplied by parallelism.** Running unbounded parallel builds across two clones once exhausted 64 GB RAM (heavy tree-sitter/SQLite/rustls deps + release LTO/`codegen-units=1`) and hard-restarted the machine. The root multiplier was **two clones with separate `target/` dirs compiling identical heavy deps at once**. Rules for agents and workflows:

- **Scope cargo per-crate** (`-p <crate>`). Never `--workspace` or `--all-features` *inside an agent* — those fan out across all 10 crates and their heavy deps simultaneously.
- **Never `cargo test -p rskim` in an agent**: it spawns a *nested* cargo (the real-cargo E2E tests in `tests/cli_test_cargo.rs`, `tests/cli_build.rs`, `tests/cli_e2e_build_parsers.rs`, `tests/cli_e2e_pkg_parsers.rs`) on top of subprocess-spawning E2E tests. Use `cargo test -p rskim --bins` / `--all-targets` (see the scoping note above).
- **Prefer `cargo nextest run -p <crate> -j 4`** for unit/integration tests, **plus `cargo test -p <crate> --doc`** for doctests (nextest cannot run doctests).
- **Never run two release/LTO builds concurrently**, and never kick off a heavy build in both clones at the same time.
- **Defer the full `--all-features` regression** to the main loop or a human, run when the machine is otherwise idle.

Modes are set via `--mode` only (no config file): `structure` (default), `signatures`, `types`, `minimal`, `pseudo`, `full`.

### Bounded output (`--max-lines`, `--last-lines`, `--tokens`)

`--max-lines N` emits at most N lines total, elision marker included — this is what the rewrite hook turns `head -N` into, so a bound the tool can exceed is not a bound (ADR-016). The sole exception is N=1: one content line plus the marker (2 lines), because spending the only slot on the marker returns a view with no code, and silently dropping the marker is the defect this flag exists to prevent. `--last-lines N` is the tail mirror: at most N lines total including the leading marker. For N=1 the same carve-out applies — 1 content line + 1 marker = 2 lines total. For `--tokens N`, the cascade escalates modes until the output fits; on tight budgets the exact elided count appears on stdout (compact marker) and the `SKIM_PASSTHROUGH=1` remedy is emitted to stderr per the ADR-011 class-1 obligation — the intended mechanism fires on every mode-cascade that elides content, but the 9-cell `{full, structure, pseudo} × {3, 5, 10}` matrix is the empirical check for this claim. The rewrite hook maps `head -N` / `tail -N` on code files to `--mode=full --max-lines N` / `--last-lines N` (verbatim slice), while `cat` stays on pseudo/structure (ADR-007); bare `head`/`tail` get the POSIX default bound of 10; signed counts (`+N`, `-N`) are never rewritten.

**Which coordinate space a marker speaks in (`rskim-core/src/transform/truncate.rs`, PF-033).** An elision marker makes two claims — *how many* lines are hidden, and *whether* a marker fires at all — and they are not stated in the same space, so name the space whenever you touch either. The **count** is in **source-line** space: it is how many lines of the user's file are hidden. **Selection, layout and the ADR-016 `max_lines` bound stay in transformed space** and are untouched by the source coordinate, because the two spaces are not affine — structure mode collapses many source lines onto one output line, and types mode inserts blank separator lines that exist in output space and in no source line at all, so a bound enforced in source space would not be the `head -N` bound ADR-016 requires. **Presence** is decided in whichever space the count is stated in (PF-033 rule 4: presence and count are two halves of one claim, and a count that is right about a gap the predicate got wrong is a new defect class rather than a partial fix — that mismatch is what produced `// ... (0 lines truncated)`, a class-1 disclosure that discloses nothing while spending an ADR-016 budget line). As it stands only the **leading** marker is decided purely in source space (`omitted > 0`); the **gap** and **trailing** markers require BOTH a transformed gap AND `omitted > 0`, so a source gap the transformed cursor cannot see is still undisclosed — signatures mode joins its spans contiguously and hits exactly that, pinned with its exact shortfall by `signatures_max_lines_undisclosed_source_lines_are_pinned` in `crates/rskim-core/tests/truncation_markers.rs`. Source space is used **only when every selected span carries a `source_range`** (`collect::<Option<Vec<_>>>()` is the all-or-nothing gate, materialised once): one unmigrated producer degrades the whole render back to transformed-space counts rather than mixing two spaces inside one set of markers — PF-033 rule 1, one coordinate space per render.

### Subcommands

Most subcommands wrap a dev tool (cargo, git, npm, pytest, eslint, docker, psql, grep, …) and compress its output — run `skim --help` for the full catalog. The ones with non-obvious behavior:

- `search` — n-gram code search over a project index. Build/update: `skim search --build` (incremental), `skim search --rebuild` (full), `skim search --update` (refresh if stale); all accept `--root`. (The `index` positional subcommand was removed in #375 — `skim search index` is now a query for the word "index".) Query: `skim search <text>` (`--limit`, `--json`, `--stats`). Pagination: `--offset N` skips `N` verified results and is honored on ALL arms — pure-lexical, compound text+`--ast`, blast-radius, and the standalone temporal arms (`--hot`/`--cold`/`--risky`/`--blast-radius` without a text query). A bounded-page notice is printed to stderr when `has_more=true` to detect the last page without the unsound `len < limit` heuristic. Temporal sort/filter: `--hot`/`--cold` (hotspot score), `--risky` (fix-risk), `--blast-radius FILE` (co-change peers). Positional: `--phrase` (ordered, contiguous), `--near N` (any order, span ≤ N word tokens), `--phrase --near N` (ordered AND span ≤ N — PhraseNear composition; narrower than bare `--near N`, never wider; identity: `--phrase --near (k-1)` == `--phrase` for a k-word query). Both flags compose with every text arm including `--ast`, `--blast-radius`, and temporal sort; inert on non-text arms (notice to stderr). `verify_mode` (`"phrase"` / `"near"` / `"phrase_near"`) is added to `--json` output for non-default modes (`skip_serializing_if` for Substring). When temporal ranking cannot be served (missing/corrupt/newer-schema/empty temporal data, or repository mismatch), `--json` carries a `degraded` array of objects (each with `subsystem`, `reason`, `requested`, `applied`, `message`, `remediation`); every element currently has `subsystem: "temporal"`. `message` is the stderr notice text **without** the leading `skim search: ` program-name prefix (every emit site prints `skim search: {message}`, so `stderr.contains(message)` holds byte-for-byte but the two strings are not equal); prepend the prefix yourself if you need the stderr line verbatim. For an empty temporal DB on a shallow clone (`meta.is_shallow` = 1) both `message` and `remediation` name `git fetch --unshallow` first, matching the build-time zero-row notice (AD-414-25). The standalone `--blast-radius FILE` arm carries the same array as the composite `text --blast-radius` arm, with `applied: "none"` because no result set is served (AD-414-24). The standalone `--ast` arm emits the degraded notice on stderr only — `format_ast_json` cannot carry `degraded` in this release (#483). A structurally inconsistent lexical or AST index is repaired by an automatic rebuild instead and produces no `degraded` entry. The field is absent on healthy queries (`skip_serializing_if`) (#414). Structural: `--ast <pattern>` — a named pattern (`try-catch`, `nested-loop`, `god-function`, …) or containment query (`for_statement > block`); composable with a text query, `--phrase`, `--near`, `--lang`, `--hot`/`--cold`/`--risky`, `--blast-radius`, `--limit`, `--offset`, and `--json`; degrades gracefully when heatmap data is absent (warns to stderr, returns unsorted, exit 0). Limitation: single-node queries (no `>` separator) are rejected (#283, unigram index not yet built). Composite ranking: `--weights lexical,ast,temporal` (default `0.5,0.3,0.2`, ratios only — not normalized, zero and non-sum-to-1 allowed, negative/NaN/inf rejected) tunes the `--blast-radius` RRF ranking (#200). `--stats --json` carries `git_head_state` (`"resolved"` / `"unresolved"` / `"not_a_repo"`) — the LIVE resolution status at query time, distinct from `git_head`, which is the manifest's HEAD-at-last-build, so `{"git_head": null, "git_head_state": "resolved"}` is a legal transient (#413) — and `temporal_state` (`"ready"` / `"empty"` / `"corrupt"` / `"newer-schema"` / `"missing"`) reporting the temporal DB's health at query time (#414); `staleness` (`"current"` / `"stale (HEAD changed: <prev8>…→<cur8>…)"` / `"stale (no HEAD recorded)"` / `"stale (working tree changed: N modified, N added, N removed)"`) reporting the lexical index staleness state at query time (F5 / #414). **`--stats` reports on an index; it never creates one (AD-414-23):** with no `index.skidx` in the cache dir it prints `{"error":"no index found","cache_dir":"<path>"}` on stdout and exits 1 (text mode: the `no index found — run 'skim search --build' first` guidance plus the cache-dir line on stderr, exit 1) — the #413 AC21 contract. The AC-14 self-heal repairs a structurally broken index that exists; it does not build a missing one, so the fifth `StalenessCheck` value, `"no index"`, is an internal cold-start verdict that `--stats` never reports. **Snapshot asymmetry (AD-414-10):** `git_head`, `temporal_state`, and `staleness` are captured from the PRE-self-heal state; all other fields (`file_count`, `skipped`, `ast_coverage`) are from the post-heal state. A `temporal_state` of `"missing"` or `"corrupt"`, or a `staleness` of `"stale (no HEAD recorded)"` after deleting `index.skpost`, can therefore coexist with a valid `file_count` — this is the intended observable contract (AC-15/AC-22). `--install-hooks`/`--remove-hooks` resolve the hooks directory for linked worktrees, submodules, and plain repos the same way git does (`git rev-parse --git-path hooks`): a linked worktree uses the shared `<commondir>/hooks` and therefore affects **every worktree of the clone**, a submodule follows the gitdir pointer to `<super>/.git/modules/<name>/hooks`, and a plain repo uses `<root>/.git/hooks` as before; both commands print the absolute resolved directory and disclose the clone-wide scope on stderr (#413). A `--root` that is a subdirectory of a git repository but has no `.git` entry of its own is **refused** — the command exits with an error naming the enclosing repository so you can re-run with the correct `--root`.
- `heatmap` — git-history risk/coupling analysis: churn, co-change, stability, fix-after-touch (`--json`, `--since`, `--window`, `--path`, `--insights`).
- `init` — install skim as an agent hook (Claude/Cursor/Codex/Gemini/Copilot/Crush); `--wrappers` adds PATH wrappers for sub-agent interception; `--permissions` seeds consent-gated allowlist entries (tiers: seed|mirror|blanket); `--dev` installs a **dev-pinned** hook, which waives the commit-equality gate and *nothing else* (version and pinned-binary format are still enforced, `pin_is_current` is untouched) so an in-place rebuild stops defeating the idempotent fast path. The script keeps its REAL `SKIM_HOOK_COMMIT` and declares dev-ness with one additive line, `export SKIM_HOOK_DEV=1`; the waiver is honoured only when the script's integrity is `Verified` (not merely "not tampered"). Dev-ness is a property of the **invocation**, not sticky state: a plain `skim init` reverts it and prints `dev-pinned -> pinned`, so there is no `--undev`; `--dev --force` is the re-stamp. **ADR-019 is the canonical entry for `--dev`** — everything in this bullet is its ruling. The source comments in `cmd/init/{flags,state,install}.rs`, `cmd/hooks/mod.rs` and `cmd/doctor/mod.rs` cite **ADR-014** instead (16 citations; ADR-019 appears in no source file under `crates/rskim/src`), and the two carry different force: ADR-014 is the broader ruling that skim's binary-provenance machinery is **advisory, not enforcing**, and ADR-019 is the decision ADR-014's amendment directed. Follow the code's ADR-014 pointer to the rationale; read ADR-019 for what `--dev` actually does (applies PF-032 — a ledger entry's clauses are not uniformly normative, so cite the one that decided your question).
- `stats` — token analytics dashboard (`--since`, `--format json`, `--verbose`, `--clear`).
- `doctor` — provenance check: reports the running binary (path + commit), every `skim` on `$PATH` with its commit and which one wins, hook pin state per agent (pinned binary path vs running binary path; a path mismatch is advisory `⚠` and does not cause exit `1`), wrapper directory, and cache/analytics locations. Exit `0` healthy / `1` on version mismatch, commit mismatch, tampered script, or unreadable script — works as a CI pre-flight. **Dev-pinned installs:** doctor has no `--dev` flag and never sees one, so it keys entirely off what the installed hooks *declare* — a hook whose dev marker clears the `Verified` integrity gate renders as `⚠ … dev-pinned (binary commit <sha>)`, carrying both the commit the install froze and the one the running binary was built from (their distance is how old the dev install is), and the behind-HEAD staleness count is demoted from `✗` + exit `1` to an advisory `⚠` that still prints the count. When no hook is dev-pinned, every line and the exit code are byte-identical to before the feature existed. `skim doctor | grep dev-pinned` is the intended CI guard for "is this machine on a dev pin", and it fires on every branch a credible dev declaration can reach — including the two `✗` drift returns, so a dev-pinned hook with a **version** mismatch (which the marker does not waive) still carries the `dev-pinned` token while exiting `1`. The guard answers that question, not "is this machine healthy" — read the exit code for that. The `Tampered` and `Unreadable` returns omit the note by construction: `dev_pinned` is `honour_dev_declaration`, which requires `Verified`. (A dev declaration under `Tampered`, `Unreadable` or `NoManifest` is not honoured at all, by design — PF-016.) Commit resolution reads `--version` output rather than a `--commit` flag, so it correctly identifies binaries that predate `skim doctor` itself.
- `discover` / `learn` / `rewrite` — scan agent sessions for missed optimizations, learn error-retry correction rules, and rewrite commands into skim equivalents.

### Two interception surfaces (they work differently — don't conflate them)

skim intercepts a sub-agent's shell command through **two independent mechanisms**, and only one of them rewrites anything. Confusing them produces false coverage claims (e.g. "flag preservation verified on both surfaces" — it can't be; see below).

1. **Rewrite engine** — the PreToolUse hook and the `skim rewrite` CLI. Operates on the command *as text, before it runs*: `cmd/rewrite/` `try_rewrite()` transforms the string `grep -rn x` → `skim grep -rn x`. This is the **only** surface where flag preservation (Fix A — don't drop `-rn` during the rewrite), corruption-bail (Fix C), and pipe-source passthrough (Fix E, gated on `is_bare_cat_pipeline` — `<cmd> | cat` is rewritten while `| cat > f`, `| cat | tee f`, and `| cat -n` are refused) exist — they are properties of the *text transformation*.

2. **PATH wrappers** — `skim init --wrappers` symlinks `~/.skim/bin/<tool>` → the skim binary (with `~/.skim/bin` first on `PATH`) so sub-agent shells route through skim even when they bypass PreToolUse hooks. Here skim *is* the tool: the OS runs the binary with `argv[0]=<tool>`, `main()` calls `strip_skim_wrappers_from_path()` as its very first statement (before any thread spawns, so the real tool is found and recursion is impossible), then `detect_argv0_dispatch()` returns the tool name and args; `main()` interposes a fidelity gate (#370): `stdout_should_serve_raw()` compresses **iff fd 1 is a terminal (`isatty`) or a FIFO**, and bails to `cmd::run_inherited_passthrough` for every other sink — regular files, non-terminal character devices (`/dev/null`), sockets — so raw bytes reach them unmodified (#317); otherwise it calls `cmd::dispatch_for_wrapper(tool, args)`. `dispatch_for_wrapper` is a one-line tag that calls the private `dispatch_inner(Surface::Wrapper, …)`; the D3/D4/D5 wrapper gates live **inside** `dispatch_inner` behind `if surface == Surface::Wrapper { … }`, so they fire on every call that passes `Surface::Wrapper` — structurally impossible to bypass by calling the shared core directly. **D5** uses `interactive_tool_for` (not `require_flags_for_tool`) and routes via `run_inherited_passthrough` (inherited stdio, not piped); `sqlite3` has `require_flag: &[]` yet is interactive — the two predicates are deliberately distinct concepts. **`try_rewrite` is never called**. Flags arrive as ordinary argv and pass to the handler unchanged; there is no rewrite step to "preserve" them through. `SKIM_PASSTHROUGH=1` is the escape hatch. Wrapper install/uninstall only ever touches symlinks whose target stem is `skim`/`rskim` — never regular files.

**Which surface decides what (stdout destination).** Each surface can observe something the other structurally cannot, so neither is authoritative alone:

- **`fstat` is ground truth, and wins wherever it can see.** It knows a regular file / char device / socket after the shell has already wired fd 1 up, when no redirect token remains in argv. `isatty(1)` — not `FileType::is_char_device()` — is what identifies a terminal; using the file-type bit as an `isatty` proxy misclassifies `/dev/null`, `/dev/zero` and `/dev/random` as terminals and compresses into them.
- **A pipe is ambiguous at the fd level**, and this is the one gap `fstat` cannot close: `| cat` (compress — skim's core value) and `| tee out.txt` / `$(…)` (compress = data loss) are the same FIFO. Only the rewrite engine sees pipeline *shape*. It records its verdict via `command_needs_exact_bytes` (`cmd/rewrite/compound.rs`) in a force-raw sidecar marker, which the wrapper discovers by ancestry walk (`session_sidecar::read_force_raw`). The marker is set *or cleared* by every hook invocation that reaches command extraction, so it never outlives a command the hook actually processed; five early exits (passthrough mode, AwarenessOnly agents, stdin read error, JSON parse error, missing command field) skip the write, and a marker left behind by one of them lives until the next processed command or the 300 s reap; the 5 s hook watchdog's `process::exit(0)` can also pre-empt the write. **The key is `{ppid}.{tool}.raw` — PID *and* tool name.** PPID alone is not a command identity: every command an agent runs shares that PID, so a PPID-only key made one command's verdict decide unrelated concurrent, background, and nested-sub-agent wrapper invocations (and let their clears delete a live marker). The tool component comes from `command_heads`, the command heads the hook saw; a shape that defeats head extraction (`$(…)`, backticks, process substitution) falls back to the wildcard `{ppid}.raw`, which matches every tool. Additionally, `pipe_consumer_needs_exact_bytes` returns `true` for `Bail`-split commands that contain a `|` — a conservative fallback that marks complex pipeline shapes (heredocs, subshells, backticks enclosing a pipe) as needing exact bytes rather than silently passing them through compression. **Accepted limitations:** the marker exists only when the hook fires — a bare wrapper invocation with no PreToolUse hook gets `fstat`-only behaviour; and two *same-tool* commands under one agent still share a key, so a concurrent `git status` can clear a live `git log | tee f` marker. Both fail toward compression, and for a FIFO wired to a byte-exact consumer (`| tee f`, `| sha256sum`) that is byte loss, not a lossless fallback: measured 304 bytes written instead of 6803, silently. The same-tool clear is a narrowed remnant of the pre-marker behaviour; the hook-less case is pinned by `no_hook_means_fstat_only_behaviour`. A third accepted limitation — PID reuse — occurs when a PID is recycled within the 300 s `FORCE_RAW_MAX_AGE` window: a new process finds the prior process's stale marker and serves raw instead of compressing. Unlike the same-tool key collision and the hook-less case, PID reuse fails toward lossless compression (extra raw bytes, none lost).
- **The rewrite engine's text scan is a hint, not an authority.** `stdout_redirected_to_file` tracks fd state left-to-right so `cmd 2>f >&2` (stderr to a file, then fd 1 dup'd from it) is recognised as a stdout→file redirect. The explicit-subcommand path (`skim git log > out.txt`) is deliberately NOT `fstat`-gated: the user typed `skim` there, and that path cannot tell a user-authored `skim …` from a hook-injected one.

**Testing / verification implication:** the two surfaces share the per-tool *handlers* (output compression) but NOT the dispatch front-end. A test that drives the `--hook`/`rewrite` path does **not** exercise the wrapper path, and vice-versa. When verifying behavior — and when confirming Snyk/CI actually cover a change — identify *which* surface a test hits and cover both where the behavior could diverge. The rewrite *text-transformation* guarantees (flag preservation, text-scan corruption-bail, pipe-source passthrough via `is_bare_cat_pipeline`) are rewrite-engine-only and do not apply to the wrapper surface. The stdout-destination guarantee, however, exists on *both* surfaces via distinct mechanisms: the rewrite engine uses `stdout_redirected_to_file` / `command_needs_exact_bytes` (a text scan before exec); the wrapper uses `stdout_should_serve_raw` (`fstat` + `isatty` on fd 1 after the shell has already redirected) plus the force-raw marker. Do not conclude that wrappers have no output-fidelity protection (#370). The helpers `arg_matches_flag` and `args_before_separator` are shared across both surfaces (D3/D4/D5 in the wrapper gate and the rewrite-engine flag checks both import them from the same module), so flag-matching semantics — including the `--` separator cut-off — are identical on both paths. The full 9-destination × 2-surface matrix is pinned in `crates/rskim/tests/cli_stdout_destination.rs`.

## Environment Variables

- `SKIM_PASSTHROUGH=1` (or `--passthrough` CLI flag) — bypass compression and exec the real tool with raw argv, at the structural convergence gate in `cmd/dispatch.rs` — the `is_passthrough_mode()` gate, conjoined with `is_meta_subcommand`, the `env` exclusion and `handler_reads_stdin`. **It is not universal — see the two exceptions below; "bypasses all compression" is the intent, not the measured behaviour.** The `--passthrough` flag strips skim-only flags from the forwarded argv so the real tool never sees flags it does not understand. Stripped for all tools: `--show-stats`, `--passthrough`, `--debug` (only when the tool does not own that flag), `--max-lines N`/`=N`, `--tokens N`/`=N`, `--last-lines N`/`=N`, `--line-numbers` (long form only; `-n` is not stripped). Additionally stripped for `git` only: bare `--json` and `--mode`/`--mode=<val>`. Nothing is stripped after a bare `--` end-of-options separator. Exception 1 — `env`/`printenv`: `SKIM_PASSTHROUGH=1` does not bypass credential redaction, and the control is **two independent layers plus a third, separately-scoped gate** (PF-012, defense in depth) — flattening them into one function is how an audit concludes the control is gone. (a) The **convergence gate** excludes `env` by **literal name** (`subcommand != "env"`), so that one command never reaches the hatch at all. (b) The **per-handler `never_passthrough: true`** flag on `cmd/file/env.rs`'s `CONFIG` — which both `skim env` and `skim printenv` route to — is the execution-layer refusal (`cmd/execution.rs`: `let passthrough = is_passthrough_mode() && !never_passthrough`), reached whenever the convergence gate declined. (c) `redaction_is_mandatory` (matching `env` **and** `printenv`) is the **structural** gate, and it guards NEITHER of the two above: its own rustdoc names its consumers as the *other* raw-serve paths — `main.rs` D2b (`stdout_should_serve_raw` / `force_raw_requested` → `run_inherited_passthrough`) and `dispatch_inner` D4 (the skip-flag gate that would otherwise let `env -u HOME` dump the whole environment). So do not go looking for passthrough coupling inside `redaction_is_mandatory`; there is none, by design, and its absence is not evidence the hatch is unguarded. **Asymmetry worth knowing before you rely on it:** `printenv` is named by (b) and (c) but NOT by (a)'s literal, so under `SKIM_PASSTHROUGH=1` it depends on the convergence gate declining — i.e. on `handler_reads_stdin` being true, which for a bare `skim printenv` off a TTY it is — to reach the handler that redacts. Source-read, not measured; measure before treating `printenv` and `env` as equivalent on this path. **Exception 2 — the multi-level dispatchers (`cargo`, `dotnet`, `go`, `swift`), off a TTY**: the gate declines whenever `handler_reads_stdin` is true, and `handler_visible_args` strips a leading non-flag token for those four tools, so `skim cargo check` reduces to an EMPTY arg slice and `should_read_stdin` (`!stdin.is_terminal() && no_real_args`) returns true — in every agent harness, CI job and pipeline, i.e. exactly where the escape hatch is reached for. The command then falls through to the compressed handler, and the build family has no `SKIM_PASSTHROUGH` branch of its own: `cmd/build/mod.rs::run_parsed_command` always spawns the tool, but it does **not** always summarise — it has three arms and two of them serve raw. It summarises only on the ADR-001 guard's `Keep` arm; the guard's `Passthrough` arm and the already-`passthrough` tier-3 arm both emit the child's bytes verbatim. So `SKIM_PASSTHROUGH=1 skim cargo check` returns the compressed summary **when the guard elects `Keep`**, never because the hatch was honoured, and serves raw otherwise. Bare `skim cargo build` was measured returning **0 bytes on stdout** — re-measure per descriptor rather than quoting that figure, because `1993063` (*fix(build): preserve the child exit code and keep stderr on fd 2*) has since moved the child's diagnostics off fd 1. Interactively the same command works, because a terminal stdin makes `should_read_stdin` false and the gate fires. To get raw bytes out of a build tool off a TTY, run the tool directly rather than through `skim`. **Both build-family raw arms now write through `emit_raw_passthrough_split`**, which is byte-faithful by construction and so diverges from the pre-split emission in two user-visible ways — neither is an oversight and neither should be "restored": child diagnostics **stay on fd 2** instead of being merged onto fd 1 (so `skim cargo fmt --check > out.txt` captures less than it did, and `2> err.txt` captures more), and **no trailing newline is appended** on either arm, so a child whose output does not end in `\n` is forwarded without one. **PF-024 is not retired by the `gh` fix** — it is closed for `gh` and open for the whole build family: `cargo.rs` injects `--message-format=json` whenever the user supplied none, and both the ADR-001 guard baseline and the raw arm then serve that injected NDJSON to someone who typed `skim cargo build`, so the guard's "did I help?" question is asked against a command the user never ran. Neither `raw_override` nor `RawFallback` appears anywhere under `cmd/build/`. Indefinite commands (`vite dev`, `jest --watch`, bare `skim vitest`) auto-pass-through live; use `skim vitest run` for a compressed one-shot.
- `SKIM_DEBUG=1` (or `--debug`) — enables raw-fallback diagnostic banners on stderr for no-loss raw-fallback paths (see **Stderr notice taxonomy** in Design Constraints below; loss-bearing elision markers and the ADR-008 transparency marker are unconditional and not gated by this variable). In hook mode the startup provenance line goes to `hook.log`, never stderr (GRANITE #361 Bug 3); drift events are also logged to `hook.log` unconditionally — `skim doctor` is the primary on-demand diagnosis path.
- `SKIM_SESSION_ID` — analytics session attribution; priority sidecar > env > `--session-id` flag (flag is a forward-compat fallback only — the hook no longer injects it). Set it alongside the PATH export so sub-agents inherit it.
- `SKIM_CACHE_DIR` — relocates **all** skim cache state: parser cache (`.json` files),
  tee output (`tee/`), and the **default** `analytics.db` location. A usable value **is**
  the cache root and is used as-is (no `skim` suffix is appended by the resolver);
  the platform path is only the fallback arm. `cache.rs::cache_root_from` treats
  an empty value as unset, and also a **whitespace-only** one — but only when the path is
  valid UTF-8. A **non-UTF-8** `OsStr` path is deliberately never trimmed and never
  rejected: it is a valid filesystem path and is used unchanged. Only when the value is
  unset by those rules does it fall back to `dirs::cache_dir()/skim` — `~/Library/Caches/skim`
  on macOS, `~/.cache/skim` on Linux. **Caveat:** pre-existing analytics history at the
  old default `analytics.db` is **not migrated** — setting this variable for the
  first time causes `skim stats` to start from an empty DB at the new location; move
  the old file manually if you want to preserve history.
- `SKIM_ANALYTICS_DB` — overrides the analytics DB path directly; **takes precedence over
  `SKIM_CACHE_DIR`** for the DB location. When `SKIM_ANALYTICS_DB` is set, the DB is
  opened at that exact path regardless of `SKIM_CACHE_DIR`. To isolate all skim state
  in a sandbox it is sufficient to set `SKIM_CACHE_DIR` alone (the default analytics.db
  moves with it).
- `SKIM_DISABLE_ANALYTICS=1` — disable recording. `SKIM_INPUT_COST_PER_MTOK` — $/MTok for cost estimates (default 3.0).
- `SKIM_WRAPPERS_DIR` — overrides the `~/.skim/bin/` wrapper symlink directory used by `skim init --wrappers` and `skim init --uninstall`. Primarily used in tests via `skim_sandboxed()` to redirect wrapper installation into a TempDir sandbox so real `~/.skim/bin/` is not touched. An empty value is treated as unset (falls back to `~/.skim/bin`).
- Session-provider overrides for `discover`/`learn`/`agents`: `SKIM_PROJECTS_DIR`, `SKIM_CODEX_SESSIONS_DIR`, `SKIM_COPILOT_DIR`, `SKIM_CURSOR_DB_PATH`, `SKIM_GEMINI_DIR`, `SKIM_CRUSH_DIR`.
- **Agent config-dir overrides** (read by `skim init` / `init --uninstall` / `doctor` — these are the agents' *own* variable names, not `SKIM_`-prefixed): `CLAUDE_CONFIG_DIR`, `CURSOR_CONFIG_DIR`, `GEMINI_CONFIG_DIR`, `COPILOT_CONFIG_DIR`, `CODEX_CONFIG_DIR`, `CODEX_HOME`, `CRUSH_CONFIG_DIR`. Each redirects that agent's hook script, settings file, permissions sidecar, and guidance file (`GEMINI.md`, `copilot-instructions.md`, …) away from the `~/.<agent>/` default. **Two resolvers, and Codex is the one place they read DIFFERENT variables** — do not treat the list as one namespace: `DetectionEnv::from_process` (`cmd/init/flags.rs`) reads `CLAUDE_CONFIG_DIR`, `CURSOR_CONFIG_DIR`, `GEMINI_CONFIG_DIR`, `COPILOT_CONFIG_DIR`, **`CODEX_CONFIG_DIR`** and `CRUSH_CONFIG_DIR`, and governs the hook script, settings, permissions sidecar and agent detection — i.e. everything install and uninstall touch; `InstructionEnv::from_process` (`cmd/session/types.rs`) reads `CLAUDE_CONFIG_DIR`, **`CODEX_HOME`**, `CRUSH_CONFIG_DIR`, `GEMINI_CONFIG_DIR` and `COPILOT_CONFIG_DIR`, and governs the guidance file only. **It has no Cursor entry, and neither resolver redirects Cursor's guidance file — `CURSOR_CONFIG_DIR` does not reach it at all.** `inject_guidance` → `resolve_instruction_path` → `AgentKind::instruction_file` returns a **cwd-relative** `.cursor/rules/skim.mdc` for project scope and `None` for global (Cursor has no file-based global config; pinned by `test_instruction_file_cursor_global_unsupported` in `cmd/session/types.rs`). So **sandboxing Cursor's `.mdc` means controlling the process's cwd, not an env var** — no combination of the variables in this list will keep it out of the directory a test happens to run in. (`rules_dir()` is a different thing: it is used by `cmd/learn.rs` for the corrections file, never by init.) So for Codex, `CODEX_HOME` alone redirects the guidance file and leaves install/uninstall pointed at the real `~/.codex`; `SANDBOX_REDIRECTED_VARS` in `tests/common/mod.rs` sets both, to the same path, for that reason. Do not confuse any of these with the `SKIM_GEMINI_DIR` / `SKIM_COPILOT_DIR` session-provider overrides above, which point at transcript directories and have no effect on install/uninstall. Any test that shells out to `skim init`/`--uninstall`/`doctor` must set them (use `common::skim_sandboxed`) or it will mutate the developer's real home directory. **Environment is only one of the two sandbox axes**, and setting every variable in this list still does not confine a test: `skim init` resolves a project root by walking ancestors of the process working directory, which no variable here can redirect — that is how real `.git/hooks` entries were getting written into this clone. `skim_sandboxed_with_bin` pins the cwd axis as well; use it rather than assembling the env by hand.

## Design Constraints

**MUST:** stream to stdout (never write intermediate files) · prefer `&str` slices over allocation in the hot path · tolerate incomplete code (rely on tree-sitter error nodes) · stay under 50ms for 1000-line files (benchmark regressions block) · fail loud with actionable messages, never silently · modes via CLI flags only, no `.skimrc` · **compress, never truncate** (#317): wrappers may re-encode output but never show less than the raw tool; an unavoidable safety bound must use `output::elision_marker` (exact counts + `SKIM_PASSTHROUGH=1` hint); unexpected non-zero exits forward raw output instead of compressing; rewrites must reconstruct the command byte-faithfully or bail (never emit a command that errors or changes semantics). **git diff enhancement view must fit within the raw budget** — any enriched render (e.g. hunk-scoped AST breadcrumbs) is guarded by an ADR-001 net-savings check; if enrichment expands the output beyond the raw diff size, raw is emitted instead (git-diff raw-budget decision reversal: the unguarded enhancement view was replaced by a guardrail-protected one). A breadcrumb line in that view is prefixed `~` — a fourth line prefix beside git's `+`, `-` and space, marking a declaration header skim pulled in from outside the hunk rather than a line git printed; it is a one-character substitution on a line emitted either way, so it costs zero net bytes, and no per-diff legend is emitted because ADR-003 already records this view at 2-5x raw on large diffs (the same budget that makes `write_hunk_boundary` withhold its `@@` line on single-hunk files, ≤29 B per hunk otherwise). That git-diff guard is the ADR-001 check in its **uncharged** form; the charged form — where a class-1 stderr disclosure is priced into the same verdict — lives on the file-transform path and is described under **Stderr notice taxonomy** below.

**Stderr notice taxonomy (ADR-011):** Every new `stderr` notice must be classified before it is added — (1) **loss-bearing markers** (elision markers with exact counts + `SKIM_PASSTHROUGH=1` hint; ADR-008 lossy-view transparency marker) fire when the reader sees less/different from raw and are **unconditional**; (2) **no-loss raw-fallback banners** (guardrail chose raw, unexpected exit, tool killed) fire only on lossless paths and are **gated behind `SKIM_DEBUG`/`--debug`** (`crate::debug_log!` / `io::sink()`). If a notice can fire when the reader sees less/different from raw, it is a marker (always on); if it fires only on a lossless raw fallback, it is a banner (debug-gated). Do not re-conflate the two classes. (3) **On the file-transform path a class-1 marker is CHARGED against the ADR-001 net-savings decision**, so a marker is an *input* to view selection and not only an output of it — it can tip the verdict to raw and thereby suppress itself. `output/fidelity.rs::decide_with_notice` prices the notice against the compressed side as a **differential**, `overhead = cost(notice if Keep) − cost(notice if Passthrough)`, which is `None` wherever the raw branch would print a byte-identical notice of its own; charging the absolute cost there double-counts (#519) and pushes the guard toward raw on exactly the paths where raw is also disclosed. Only `process.rs` routes through the charging entry point (`guardrail::apply_to_stderr_with_notice`); **`cmd/git/show.rs` and `cmd/git/diff/mod.rs` still call the uncharged `apply_to_stderr` shim**, and `cmd/build/mod.rs`'s `Keep` arm passes `None` deliberately (its stdout accounting still carries the success-line hole the ADR-011 census recorded, and a stderr-only charge would make a partial accounting read as a complete one — charge both together or neither). `decide` / `apply` remain charge-nothing shims on purpose, so a call site that has no notice, or has not been audited for one, cannot charge the wrong thing by omission.

**MUST NOT:** add syntax highlighting (use `bat`), linting (use linters), type checking (use `tsc`/`mypy`), or LSP features — all out of scope.

**Targets:** parse+transform <50ms/1000 lines · 60–80% token reduction (structure mode) · <10ms startup · <1s for 100 files (parallel via rayon).

**Exit codes (skim's own):** `0` success · `1` general error · `2` parse error · `3` unsupported language. **Wrapped build tools forward the child's code**, so that set is NOT exhaustive for them and `$?`-keying CI scripts must read the wrapped tool's code, not this list. `cmd/build/mod.rs::resolve_exit_code` returns `max(child, derived)` — the child's status narrowed by `exit_code_from_status`, raised (and deliberately never lowered) by the parser's own failure verdict, so a gradle `BUILD FAILED` on a zero exit still fails. `skim cargo check` therefore exits cargo's `101`, and `skim make` with no makefile exits make's `2`, colliding with skim's own parse-error code. `exit_code_from_status` is fail-closed: a signal kill (`None`) and any out-of-range or negative child status (Windows NTSTATUS — `STATUS_ACCESS_VIOLATION` arrives as `-1073741819`) report **1**, never `0`, and a status above 255 saturates to 255 rather than wrapping a `256` back to `0` through a bare `as u8`. `clamp(1, 255)` rather than `clamp(0, 255)` is the whole mechanism.

## Adding a Language

**tree-sitter language:** add the `tree-sitter-<lang>` dep at the workspace version, then add an arm to each of these **exhaustive, wildcard-free** tables — the compiler rejects an omission at build time:
1. `to_tree_sitter()` (`rskim-core/src/types.rs`) — maps the variant to its grammar
2. `literal_syntax()` (`transform/literal_scan.rs`) — string/comment delimiter rules; verify the node-kind names used against the grammar's `node-types.json` at the pinned version
3. `literal_fragment_kinds()` (`transform/literals.rs`) — inner-text node kinds; same grammar-verification step required
4. `get_comment_prefix()` (`transform/utils.rs`) — single-line comment prefix

~60 min, accounting for the grammar-verification step.

**Data format (non-tree-sitter, like JSON/YAML/TOML):**
1. Add a `Language` variant in `rskim-core/src/types.rs`; return `None` from `to_tree_sitter()` and from the `get_*_node_types()` functions.
2. Implement a transform module (`src/transform/<fmt>.rs`) with security limits (max depth, max keys).
3. Route it in `Language::transform_source()` (Strategy Pattern).
4. Add the variant to `LanguageArg` in `crates/rskim/src/main.rs`.

## Release

Run `./scripts/release-prep.sh <version>` (pre-flight checks + mechanical version bumps). You still create the `release/vX.Y.Z` branch and write the CHANGELOG entry by hand. The version lives in `crates/rskim-core/Cargo.toml` and `crates/rskim/Cargo.toml` (plus the `rskim-core` dependency version) — all MUST equal the tag exactly or the build job fails. Pushing tag `vX.Y.Z` triggers `.github/workflows/release.yml`: test → build (7 targets) → GitHub Release → crates.io (`rskim-core` then `rskim`) → npm → Homebrew tap.
