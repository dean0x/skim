# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Skim** is a streaming code reader for AI agents, written in Rust on tree-sitter. It strips implementation detail while preserving structure, signatures, and types to optimize code for LLM context windows. It also compresses other agent context: test output, build errors, lint output, git diffs, logs, and raw shell commands.

**Key principle:** Skim is a *streaming reader* (`cat` but smart), not a file compressor. Output always goes to stdout for pipe workflows — never write intermediate files.

User-facing install/usage lives in `README.md`; release mechanics in `CHANGELOG.md`. This file is for working *in* the repo.

**Three `ADR-NNN` namespaces collide in this tree — resolve an anchor before you cite it.** Bare `ADR-NNN` is the global devflow ledger, `.devflow/learning/decisions-ledger.jsonl` (20 anchors, `ADR-001`–`ADR-020`); `SEARCH-ADR-NNN` is the search subsystem's local namespace (`cmd/search/**`, `rskim-bench/**`, typically paired with `AD-NNN-N` ticket IDs); `L3-ADR-NNN` is Layer-3's (`rskim-llm`, `rskim-compress`, `rskim-proxy`, `rskim-contract`; issues #427/#301/#305/#309). The numbers overlap and the bare form does not say which namespace it means, so a local decision written bare *resolves* — `ADR-007` reads as the ledger's ADR-007 (*pseudo mode preserves function return types*), a real and entirely unrelated entry. That is the one failure mode no existence check catches: the anchor greps, the row exists, the heading renders, and the citation is still wrong (PF-014, fourth direction). **The ledger is the only authoritative namespace, and `decisions-ledger.jsonl` is the only place to resolve an anchor** — `.devflow/learning/*.md` are render artifacts whose renderer **drops retired rows**, so absence from `decisions.md` is NOT evidence an anchor never existed (PF-014; a reviewer drew exactly that inference and commit `9be0d67` deleted four substantively correct citations).

## Workspace

Cargo workspace, 10 crates:
- `rskim-core` — pure transform library (parsing, modes; no I/O side effects)
- `rskim` — CLI binary (`skim`): caching, analytics, command wrappers
- `rskim-proxy` — HTTP reverse proxy foundation for Layer-3 LLM request routing (hyper + tokio; isolated from default builds)
- `rskim-research` — pinned corpus clones and corpus config loading for the search scoreboard (library only; no binary)
- `rskim-bench` — the search scoreboard (`scoreboard` bin; the search merge gate, see "Search quality gate" below)
- `rskim-oracle` — independent ground-truth oracles for the search scoreboard (the tree-sitter role oracle for definitions, calls and imports in `src/roles.rs` with `queries/roles/`; `src/structural.rs` keeps the language table the role oracle uses, and its `queries/<pattern>.<lang>.scm` have no scoring consumer); depends on no `rskim-*` crate, enforced by its `tests/independence.rs` manifest check
- `rskim-tokens` — offline + optional-network token counting (multi-provider; `net-anthropic` feature gates HTTP)
- `rskim-contract` — byte-faithful contract / guardrail layer for transcript mutation
- `rskim-llm` — LLM transcript parsing (OpenAI/Anthropic) + classifier
- `rskim-compress` — per-content-type block compression router for the Layer-3 proxy (BlockRouter, log compression)

## Architecture

```
Parser Manager (language detection)
  ↓
Language::transform_source()          ← Strategy Pattern dispatcher
  ├─ tree-sitter  (15 code langs: TS/JS/Python/Rust/Go/Java/C/C++/C#/Ruby/SQL/Kotlin/Swift/Bash/Markdown)
  └─ serde-based  (JSON/YAML/TOML — data formats, not code)
  ↓
Transformation Layer (modes: structure / signatures / types / minimal / pseudo / full)
  ↓
Streaming output (stdout, zero-copy via &str slices where possible)
```

`transform_source()` routes each language to its parser via the Strategy Pattern, avoiding special-case conditionals — each language encapsulates its own strategy.

**Non-obvious behavior (gotchas):**
- **Analytics:** token savings persist to `<cache-root>/analytics.db` (SQLite/WAL; default location — relocates with `SKIM_CACHE_DIR`, see Environment Variables), recorded fire-and-forget on background threads. The cache root is resolved by `cache.rs::cache_root_from`, which is an override-or-fallback: a usable `SKIM_CACHE_DIR` **is** the root and is used verbatim (no `skim` suffix appended), and only when none is given does it fall back to the `or_else` arm `dirs::cache_dir().join("skim")` — which is **platform-dependent**: `~/Library/Caches/skim/` on macOS, `~/.cache/skim/` on Linux. `~/.cache/skim` does not exist on a macOS dev box — read the real paths off `skim doctor` rather than assuming the XDG one, and do not describe the platform path as "the cache root" when an override is in play. `--clear-cache` clears only the parser cache, NOT `analytics.db` — use `skim stats --clear` for that. The `AnalyticsStore` trait + `MockStore` make the stats dashboard testable without a real DB. **Analytics schema migrations are two non-interchangeable idioms, and `PRAGMA user_version` governs only one of them** — `run_migrations` calls `run_versioned_migrations` (a forward-only LADDER: each rung gated on `user_version` and stamping the next number, currently topping out at 3) and then `reconcile_additive_columns` (a PRESENCE RECONCILE). The delivered-cost columns (`DELIVERED_COST_COLUMNS` = `notice_tokens`, `notice_bytes`, `served`) are added by presence-gated `ALTER`s that **stamp no `user_version` at all** — deliberately, because three lineages want a number against the same `analytics.db` and a stamp here would make another lineage's version-gated migration skip itself, fail every INSERT, and die silently in `persist_record`'s discard. **A new nullable column goes in the reconcile, not on the ladder.** Nothing downstream consults the version anyway: `query_summary` selects the delivered series row-by-row on `notice_tokens IS NOT NULL`. **Presence-gating survives a foreign `ALTER`; it does NOT survive a foreign table REBUILD**, which silently drops the columns and every measurement in them (hence the `analytics_meta` marks, which live outside `token_savings` where a rebuild cannot reach them). Not hypothetical: the live DB measured at `user_version = 5` already carries both other lineages' tables, `proxy_block_decisions` and `alignment_decisions`, and its `token_savings` is already a post-rebuild reconstruction. **Read the `HAZARD FOR WHOEVER RECONCILES THESE LINEAGES` banner in `analytics/schema.rs` before merging or reconciling with another lineage** — it also documents the `user_version = 4` orphan an earlier commit of this branch created, how to identify one, and its one-line remedy.
- **Search:** `skim search` is a scan engine (`cmd/search/`): each query reads the files, so there is no index, no cache, no git hook, no analytics row and no file written. **Universe** (`universe.rs`): every git-tracked regular file (read from the git index in process, with no `git` subprocess; gitlinks and skip-worktree entries are dropped) plus the files of an ignore-aware walk of the root (hidden and ignored files skipped, links not followed); outside a repository, the walk of the current folder only. `-g` and `-t` filter the repo-relative paths first. Each remaining file is read once under a containment check (each parent folder canonicalized once and required inside the canonical root, `O_NOFOLLOW` open, regular files only) and is admitted or counted under one `left_out` reason: `binary`, `not_utf8`, `too_large` (above 5 MiB), `unreadable`, `vanished`, `outside_root`, `symlink`. **Every matching line is listed or counted, and every bound that fires prints a marker with exact counts** (stored lines 10 000, context lines 100 000, definition lines 100 per file and 10 000 in all, parse budget 500 files / 32 MiB / 1 MiB per file, 16 words, 64 filters, fixed regex size limits). No bound reads the clock, so the labels and the order depend only on the files. **Hidden and secret-bearing tracked files (`.env`, key files) are searched and listed**; that policy is one constant (`SENSITIVE_PATH_POLICY`) and one function (`sensitive_admission`) in `universe.rs`, so the default can change to leave such files out. **Roles come from syntax, not types** (the declaration rule of `rskim-core/src/decl.rs`, the callee and import rules of `roles.rs`, the field classifier): calls are not split by definition, and a name with several definitions gets a note. Without `--root`, the root is the repository that holds the current folder (`gitdir.rs`): the walk up stops at `GIT_CEILING_DIRECTORIES`, never takes `$HOME` or `/`, adopts an ancestor `.git` only when the current user owns it (else it searches the current folder and prints a note), and outside a repository the scope is the current folder only; cwd `/` needs `--root /`. `--root DIR` follows the same rules and prints the same notes, and more than 64 ceiling entries print a note with the exact count of entries dropped. A repository that holds the root but cannot be read (no `HEAD` file, an unreadable `.git` entry) is exit 2, never a walk-only answer. **Data that skim 2.x left behind:** an index under `<cache>/search/<id>/` and a block between `# skim-search-start` and `# skim-search-end` in the `post-commit`, `post-merge` and `post-checkout` hooks. A query never touches either. `skim init` and `skim init --uninstall` remove the block and keep every foreign line, `skim --clear-cache` removes the index files, and `skim doctor` reports both as advisory lines.
- **Search quality gate (SEARCH-ADR-007, amended 2026-09-25):** the **search scoreboard** (#203) is the required merge gate for search/retrieval PRs. It is the CI job `Search Scoreboard`, which runs when a PR touches `crates/rskim/src/cmd/search/` (or the `rskim` files it imports from or is dispatched by: `cmd/mod.rs`, `cmd/execution.rs`, `cmd/dispatch.rs`, `debug.rs`, `output/mod.rs`, `analytics/mod.rs` with its `analytics/schema.rs` and `tokens.rs`, `main.rs`, plus `crates/rskim/Cargo.toml`), `crates/rskim-core/`, `crates/rskim-bench/`, `crates/rskim-oracle/`, `crates/rskim-research/`, the root `Cargo.*` or `ci.yml`, including a file renamed out of one of them (and on every push to main). A new `crate::` import from `cmd/search/` to another `rskim` file means adding that file to `SEARCH_PATHS` in `ci.yml` and to the scoreboard README ("CI") together. It drives the release `skim` end to end on four pinned corpora (skim, ripgrep, flask, zod) against oracles independent of skim's search code; nothing is built first, because each query reads the files. Recall and precision of the full list against the text universe, silent false negatives, pagination, ordering and unique paths are HARD checks (tolerance 0) with a known-failures ledger; ranking, anchor, byte and universe numbers and the cost counters RATCHET against a blessed `baseline.json`. Plain-word answers are frozen from `git grep -nw` and a hand read: `[[refs]]` (HARD `refs.recall`, `refs.calls_recall`; RATCHET `refs.call_precision`), `[[clash]]` (HARD `clash.defs_complete`, `clash.def_count`, `clash.calls_recall`), `[[stakes]]` (HARD `stakes.lines`, `stakes.files`, `stakes.counts`, `stakes.exit`), the concept `first` field (HARD `concept.first_right_top5`), and HARD `ident.def_first`, `lexical.recall_tracked` and `universe.accounted` over the text universe (every tracked text file, no language allow-list, hidden and secret-bearing tracked files included, as `git grep` lists them). The `cost.*` rows are RATCHET; the `roles.precision.<lang>` rows are RATCHET: of the `def`, `call` and `import` labels that the `[[refs]]` and `[[clash]]` pages put on files of a language, the share the role oracle confirms (a language with no label in the four corpora has no value); the `rg -nw` byte rows (`bytes.rgw_*`) are INFO in `info.reference`, never gated. A search PR must keep `scoreboard check` green: an unledgered HARD failure needs a fix, or a filed ticket plus an `[[xfail]]` entry in `crates/rskim-bench/scoreboard/known_failures.toml` (never a placeholder); fixing a ledgered bug means removing its entry (an XPASS fails the gate until you do) and re-blessing; any ratchet move in either direction, or a golden-file or corpus-pin change, needs a re-bless (`scoreboard bless --from report.json`, preferably from the CI `scoreboard-report` artifact; a ratchet regression or a HARD downgrade — `pass -> xfail`, or a blessed check that no longer runs — needs `--accept-regression "<reason>"`). Run it locally with the `scoreboard` line under Commands. Manual adversarial dog-food against ground truth (git grep, ripgrep, raw file bytes) stays required only where the scoreboard is blind: the text layout of both views and of the notices (the checks read the JSON envelope, `-l`, `-c` and the exit code), role precision outside the frozen names (`refs.call_precision` covers the `[[refs]]` names only), the split of calls by definition (not done in v1), latency (INFO only), and any new query flag. Runbook: `crates/rskim-bench/scoreboard/README.md`.

## Commands

To test changes in **this** clone, invoke its own build by path — `./target/release/skim` (refresh with `cargo build --release`). ⚠️ A bare `skim` on `$PATH` may resolve to a *different* local clone (this machine keeps parallel clones to avoid worktree churn), so it can silently exercise the wrong code.

```bash
cargo build --release          # production build
cargo test --all-features      # full test suite
cargo clippy -- -D warnings    # lint (warnings are errors)
cargo fmt -- --check           # format check
cargo bench                    # criterion benchmarks
cargo run --bin skim -- file.ts --mode=signatures   # run locally
cargo run -p rskim-bench --bin scoreboard -- check --skim-bin target/release/skim   # search quality gate (after `cargo build --release -p rskim`; ~3.6 min warm; the CI job ~7 min)
```

`rskim` is bin-only (the `skim` binary; no `src/lib.rs`) — scope its tests with `cargo test -p rskim --bins` (or `--all-targets`). `cargo test -p rskim --lib` errors with "no library targets found" (a cargo target-selection behavior, not a skim bug). `rskim-core` is a library and accepts `--lib`.

### Build/test resource limits

A machine-global `~/.cargo/config.toml` caps every cargo invocation at `jobs = 4` and `RUST_TEST_THREADS = 4`, and routes compilation through `sccache` (a compile cache shared across parallel clones). **That config file is the enforcement layer — it protects every branch and clone regardless of this doc; the guidance below exists because the cap alone can still be multiplied by parallelism.** Running unbounded parallel builds across two clones once exhausted 64 GB RAM (heavy tree-sitter/SQLite/rustls deps + release LTO/`codegen-units=1`) and hard-restarted the machine. The root multiplier was **two clones with separate `target/` dirs compiling identical heavy deps at once**. Rules for agents and workflows:

- **Scope cargo per-crate** (`-p <crate>`). Never `--workspace` or `--all-features` *inside an agent* — those fan out across all 10 crates and their heavy deps simultaneously.
- **Never `cargo test -p rskim` in an agent**: it spawns a *nested* cargo (the real-cargo E2E tests in `tests/cli_test_cargo.rs`, `tests/cli_build.rs`, `tests/cli_e2e_build_parsers.rs`, `tests/cli_e2e_pkg_parsers.rs`) on top of subprocess-spawning E2E tests. Use `cargo test -p rskim --bins` / `--all-targets` (see the scoping note above).
- **Prefer `cargo nextest run -p <crate> -j 4`** for unit/integration tests, **plus `cargo test -p <crate> --doc`** for doctests (nextest cannot run doctests).
- **Never run two release/LTO builds concurrently**, and never kick off a heavy build in both clones at the same time.
- **Defer the full `--all-features` regression** to the main loop or a human, run when the machine is otherwise idle.

Modes are set via `--mode` only (no config file): `structure` (default), `signatures`, `types`, `minimal`, `pseudo`, `full`.

### Bounded output (`--max-lines`, `--last-lines`, `--tokens`)

`--max-lines N` emits at most N lines total, elision marker included — this is what the rewrite hook turns `head -N` into, so a bound the tool can exceed is not a bound (ADR-016). The sole exception is N=1: one content line plus the marker (2 lines), because spending the only slot on the marker returns a view with no code, and silently dropping the marker is the defect this flag exists to prevent. `--last-lines N` is the tail mirror: at most N lines total including the leading marker. For N=1 the same carve-out applies — 1 content line + 1 marker = 2 lines total. For `--tokens N`, the cascade escalates modes until the output fits; on tight budgets the exact elided count appears on stdout (compact marker) and the `SKIM_PASSTHROUGH=1` remedy is emitted to stderr per the ADR-011 class-1 obligation — the intended mechanism fires on every mode-cascade that elides content, but the 9-cell `{full, structure, pseudo} × {3, 5, 10}` matrix is the empirical check for this claim. The rewrite hook maps `head -N` / `tail -N` on code files to `--mode=full --max-lines N` / `--last-lines N` (verbatim slice), while `cat` stays on pseudo/structure (ADR-007); bare `head`/`tail` get the POSIX default bound of 10; signed counts (`+N`, `-N`) are never rewritten.

**Which coordinate space a marker speaks in (`rskim-core/src/transform/truncate.rs`, PF-033).** An elision marker makes two claims — *how many* lines are hidden, and *whether* a marker fires at all — and they are not stated in the same space, so name the space whenever you touch either. The **count** is in **source-line** space: it is how many lines of the user's file are hidden. **Selection, layout and the ADR-016 `max_lines` bound stay in transformed space** and are untouched by the source coordinate, because the two spaces are not affine — structure mode collapses many source lines onto one output line, and types mode inserts blank separator lines that exist in output space and in no source line at all, so a bound enforced in source space would not be the `head -N` bound ADR-016 requires. **Presence** is decided in whichever space the count is stated in (PF-033 rule 4: presence and count are two halves of one claim, and a count that is right about a gap the predicate got wrong is a new defect class rather than a partial fix — that mismatch is what produced `// ... (0 lines truncated)`, a class-1 disclosure that discloses nothing while spending an ADR-016 budget line). As it stands only the **leading** marker is decided purely in source space (`omitted > 0`); the **gap** and **trailing** markers require BOTH a transformed gap AND `omitted > 0`, so a source gap the transformed cursor cannot see is still undisclosed — signatures mode joins its spans contiguously and hits exactly that, pinned with its exact shortfall by `signatures_max_lines_undisclosed_source_lines_are_pinned` in `crates/rskim-core/tests/truncation_markers.rs`. Source space is used **only when every selected span carries a `source_range`** (`collect::<Option<Vec<_>>>()` is the all-or-nothing gate, materialised once): one unmigrated producer degrades the whole render back to transformed-space counts rather than mixing two spaces inside one set of markers — PF-033 rule 1, one coordinate space per render.

### Symbol read (`skim FILE --symbol NAME`)

`--symbol NAME` prints the raw source lines of one named declaration; the declaration rule is `rskim-core/src/decl.rs`. The cache key puts `symbol:<byte length>:<name>|` before the path, never after the numeric fields, because a name at the end collides with a file whose own name spells those fields; a key without a symbol stays byte-identical. The stderr notice (lines shown, lines above and below) is a loss-bearing marker, and the cache entry stores it, so a warm read prints what the cold read printed. A symbol read records no analytics row, because the row would count the selection as a token saving.

### Subcommands

Most subcommands wrap a dev tool (cargo, git, npm, pytest, eslint, docker, psql, grep, …) and compress its output — run `skim --help` for the full catalog. The ones with non-obvious behavior:

- `search` — scan code search: `skim search PATTERN` reads the files at query time (the **Search** gotcha above has the universe, the bounds and the old data). The pattern is a literal and case sensitive by default (`-i`, `-S`, `-w`, `-F`, `-E`). A bare identifier (`^[\p{XID_Start}_$][\p{XID_Continue}$]*$`, no `-E`, no `-F`) gives the labelled view: the definition with its line range first, then each call with the function that holds it, then the other roles counted (`--all` lists every section, `--full` prints the text of long sections). One quoted argument with ASCII spaces (at most 16 words) gives the word view: the files that hold all the words first, ranked by file kind and then by count, 10 files by default, and files with fewer words follow when fewer than 3 files hold all of them. Any other pattern, and every `-E` pattern, gives the labelled view with `--all`. The flag set is closed (`parse_flags` in `cmd/search/args.rs`) and `skim search` starts no other program: `-g/--glob` and `-t/--type` (rg's own glob and type rules from the `ignore` crate, applied to repo-relative paths), `-l` and `-c` (path order, summary on stderr, `--limit` and `--offset` do not apply, no `-C`, `--all`, `--full` or `--json`), `-C N` (0 to 100), `--limit`, `--offset`, `--json` (one compact object on one line), `--root DIR` (a subfolder of a repository searches that subtree only) and `-n` (accepted and ignored). One pattern only; `--` ends the flags. The removed 2.x flags (`--ast`, `--hot`, `--cold`, `--risky`, `--blast-radius`, `--weights`, `--phrase`, `--near`, `--build`, `--rebuild`, `--update`, `--stats`, `--install-hooks`, `--remove-hooks`, `--lang`, `-j`; `REMOVED_FLAGS` and `REMOVED_SHORT_JSON` in `args.rs`) exit 2 with a message that names the replacement, print nothing on stdout and write nothing to disk. Exit codes: see the `skim search` exception under Design Constraints. Per-stage timings go through `crate::debug_log!` (`SKIM_DEBUG=1`).
- `git` — wraps `status|diff|fetch|log|show|commit|push`. Three non-obvious rules. **(a) The machine-contract passthrough gate (ADR-022).** `MACHINE_CONTRACT_FLAGS` in `cmd/git/mod.rs` is a closed set — `--porcelain`, `--null`, `--stat`, `--shortstat`, `--numstat`, `--name-only`, `--name-status`, `--raw`, `--check`, `--quiet`, `-q`, `--exit-code`, `--graph`, `--format`, `--pretty`, plus cluster-aware `-z` via `CONTRACT_SHORT_OPTS` — whose presence serves real git bytes verbatim, in a match guard **ahead of every handler** and therefore ahead of every ADR-001 net-savings verdict. Read the const, never a copied list. The gate is deliberately **not** separator-aware and the short scan is cluster-wide, because the error modes are asymmetric: a false positive costs only compression (raw is byte-faithful, and `parse_tier == "passthrough"` skips the guard rather than being graded by it), while a false negative reshapes a machine contract silently at exit 0 — the whole defect class. It replaced two per-command spellings (`diff`'s stat family, `log`'s `--format`/`--pretty`), so a new contract flag is one entry rather than a fourth audit; `cmd/git/show.rs`'s own `PASSTHROUGH_FLAGS` is a strict subset the gate now reaches first. **(b) `git show <rev>:<path>` serves the blob's exact bytes** — that is git's blob-extraction syntax, so a lossy answer there is indistinguishable from the file having been different. `--mode=<m>` is the opt-in transform (it used to exit 1 with `fatal: unrecognized argument`), and a lossy `--mode` emits an unconditional ADR-011 class-1 marker on stderr. ADR-022 is the reversal; it supersedes `AD-GIT-SHOW-PSEUDO`. Byte-faithful holds for **valid-UTF-8 blobs only**: `runner.rs`'s `read_pipe`/`read_pipe_degrade_impl` fall back to `String::from_utf8_lossy`, so invalid UTF-8 reaches the blob path with `U+FFFD` already substituted (pre-existing, filed separately). **(c) The diff render's line-number column is one column over two coordinate spaces**, and the prefix byte is the only thing that names them: `-` indexes the OLD file, `+` and space the NEW one (`~` breadcrumbs carry no number). The column therefore repeats and runs backward across a `-`/`+` boundary. A second column is foreclosed, not open: `TWO_COLUMN_BYTES = 76` in `tests/cli_git_diff_budget.rs` is the size of the rejected alternative and the measured margins are 68 / 63 / 54 B across three independent fixtures — *"Do not raise the constant to silence this (PF-027)"*. So the convention is **documented, not displayed** (`print_diff_help`'s `LINE NUMBERS` block, README, `emit_patch_line`'s rustdoc), and `write_hunk_boundary` withholding `@@` on single-hunk files makes it least discoverable exactly where it is most needed.
- `heatmap` — git-history risk/coupling analysis: churn, co-change, stability, fix-after-touch. The default text view is 30 lines or fewer; `--detail <section>` and `--top` give more, and `skim heatmap <file>` gives a per-file card. All noise rules (support minimums, fix-risk lift against the base rate, bus-factor gate) live in `cmd/heatmap/noise.rs`; do not add filters elsewhere (path excludes stay in `excludes.rs`). JSON is version 2; `files[]` has the hotspot cap (10 by default), but no support minimum applies to it, so it keeps the raw values.
- `init` — install skim as an agent hook (Claude/Cursor/Codex/Gemini/Copilot/Crush); `--wrappers` adds PATH wrappers for sub-agent interception; `--permissions` seeds consent-gated allowlist entries (tiers: seed|mirror|blanket); `--dev` installs a **dev-pinned** hook, which waives the commit-equality gate and *nothing else* (version and pinned-binary format are still enforced, `pin_is_current` is untouched) so an in-place rebuild stops defeating the idempotent fast path. The script keeps its REAL `SKIM_HOOK_COMMIT` and declares dev-ness with one additive line, `export SKIM_HOOK_DEV=1`; the waiver is honoured only when the script's integrity is `Verified` (not merely "not tampered"). Dev-ness is a property of the **invocation**, not sticky state: a plain `skim init` reverts it and prints `dev-pinned -> pinned`, so there is no `--undev`; `--dev --force` is the re-stamp. **ADR-019 is the canonical entry for `--dev`** — everything in this bullet is its ruling. The source comments in `cmd/init/{flags,state,install}.rs`, `cmd/hooks/mod.rs` and `cmd/doctor/mod.rs` cite **ADR-014** instead (16 citations under `crates/rskim/src`, across those five files plus `cmd/execution.rs`); **`ADR-019` is cited under `crates/rskim/src` too — 8 times**, in `cmd/init/{install,mod,helpers}.rs` and `cmd/doctor/mod.rs` (a ninth sits in `crates/rskim/tests/cli_doctor.rs`), landing on the `--dev` mechanics themselves — the commit-equality waiver, `HOOK_DEV_MARKER` credibility, why no `--undev` exists — rather than on the provenance rationale, and the two carry different force: ADR-014 is the broader ruling that skim's binary-provenance machinery is **advisory, not enforcing**, and ADR-019 is the decision ADR-014's amendment directed. Follow the code's ADR-014 pointer to the rationale; read ADR-019 for what `--dev` actually does (applies PF-032 — a ledger entry's clauses are not uniformly normative, so cite the one that decided your question).
- `stats` — token analytics dashboard (`--since`, `--format json`, `--verbose`, `--clear`).
- `doctor` — provenance check: reports the running binary (path + commit), every `skim` on `$PATH` with its commit and which one wins, hook pin state per agent (pinned binary path vs running binary path; a path mismatch is advisory `⚠` and does not cause exit `1`), wrapper directory, and cache/analytics locations; an old search hook block and old search index data left by skim 2.x show as advisory `⚠` lines that change neither the drift verdict nor the exit code. Exit `0` healthy / `1` on version mismatch, commit mismatch, tampered script, or unreadable script — works as a CI pre-flight. **Dev-pinned installs:** doctor has no `--dev` flag and never sees one, so it keys entirely off what the installed hooks *declare* — a hook whose dev marker clears the `Verified` integrity gate renders as `⚠ … dev-pinned (binary commit <sha>)`, carrying both the commit the install froze and the one the running binary was built from (their distance is how old the dev install is), and the behind-HEAD staleness count is demoted from `✗` + exit `1` to an advisory `⚠` that still prints the count. When no hook is dev-pinned, every line and the exit code are byte-identical to before the feature existed. `skim doctor | grep dev-pinned` is the intended CI guard for "is this machine on a dev pin", and it fires on every branch a credible dev declaration can reach — including the two `✗` drift returns, so a dev-pinned hook with a **version** mismatch (which the marker does not waive) still carries the `dev-pinned` token while exiting `1`. The guard answers that question, not "is this machine healthy" — read the exit code for that. The `Tampered` and `Unreadable` returns omit the note by construction: `dev_pinned` is `honour_dev_declaration`, which requires `Verified`. (A dev declaration under `Tampered`, `Unreadable` or `NoManifest` is not honoured at all, by design — PF-016.) Commit resolution reads `--version` output rather than a `--commit` flag, so it correctly identifies binaries that predate `skim doctor` itself.
- `discover` / `learn` / `rewrite` — scan agent sessions for missed optimizations, learn error-retry correction rules, and rewrite commands into skim equivalents.

### Three interception surfaces (they work differently — don't conflate them)

skim intercepts a sub-agent's shell command through **three independent mechanisms**, and only one of them rewrites anything. Confusing them produces false coverage claims (e.g. "flag preservation verified on both surfaces" — it can't be; see below).

1. **Rewrite engine** — the PreToolUse hook and the `skim rewrite` CLI. Operates on the command *as text, before it runs*: `cmd/rewrite/` `try_rewrite()` transforms the string `grep -rn x` → `skim grep -rn x`. This is the **only** surface where flag preservation (Fix A — don't drop `-rn` during the rewrite), corruption-bail (Fix C), pipe-source passthrough (Fix E, gated on `is_bare_cat_pipeline` — `<cmd> | cat` is rewritten while `| cat > f`, `| cat | tee f`, and `| cat -n` are refused), and the **PATH-resolvability bail** exist — they are properties of the *text transformation*. The last is a global bail evaluated only once a rule or a `cat`/`head`/`tail` handler has produced a rewrite (never on the raw first token of an arbitrary command): `runner::program_resolves` declines the rewrite when `Command::new(<program>)` could not find the binary, so the real command runs untouched rather than being rewritten into a `skim <tool>` that cannot spawn. It answers *"would skim spawn this?"*, **not** *"would the shell run something for this?"* — a shell **function** or alias is invisible to any `PATH` probe by construction, and `strip_skim_wrappers_from_path()` has already run, so the probe sees a modified `PATH`. A deliberate conservative approximation: a false decline costs compression, a false accept costs the reader their answer (PF-038). For the ten `npx <tool>` rules (`NPX_LOCAL_BIN_RULES`), the PreToolUse hook rewrites only when `<tool>` is executable in `node_modules/.bin` of the hook `cwd` or a parent up to the repository root, and the rewrite puts `--via-npx` after all the rewritten tool words (`skim prettier --write --via-npx src`); a later compound segment is never an npx rewrite. The handler re-checks the bin and starts `npx --no-install <tool> …`; `--via-npx` is read only at that fixed position, and only on the explicit surface.

2. **PATH wrappers** — `skim init --wrappers` symlinks `~/.skim/bin/<tool>` → the skim binary (with `~/.skim/bin` first on `PATH`) so sub-agent shells route through skim even when they bypass PreToolUse hooks. Here skim *is* the tool: the OS runs the binary with `argv[0]=<tool>`, `main()` calls `strip_skim_wrappers_from_path()` as its very first statement (before any thread spawns, so the real tool is found). On the wrapper surface it also moves to the end of PATH every folder whose `<tool>` is this same skim binary (same device and inode), up to the first other executable `<tool>`, and exits 126 when the first `<tool>` left is still skim; `SKIM_DEPTH` (limit 32) and the `SKIM_WRAPPER_PARENT` marker stop any chain that still re-enters skim, with exit 126. Then `detect_argv0_dispatch()` returns the tool name and args; `main()` interposes a fidelity gate (#370): `stdout_should_serve_raw()` compresses **iff fd 1 is a terminal (`isatty`) or a FIFO**, and bails to `cmd::run_inherited_passthrough` for every other sink — regular files, non-terminal character devices (`/dev/null`), sockets — so raw bytes reach them unmodified (#317); otherwise it calls `cmd::dispatch_for_wrapper(tool, args)`. `dispatch_for_wrapper` is a one-line tag that calls the private `dispatch_inner(Surface::Wrapper, …)`; the D3/D4/D5 wrapper gates live **inside** `dispatch_inner` behind `if surface == Surface::Wrapper { … }`, so they fire on every call that passes `Surface::Wrapper` — structurally impossible to bypass by calling the shared core directly. **D5** uses `interactive_tool_for` (not `require_flags_for_tool`) and routes via `run_inherited_passthrough` (inherited stdio, not piped); `sqlite3` has `require_flag: &[]` yet is interactive — the two predicates are deliberately distinct concepts. **`try_rewrite` is never called**. Flags arrive as ordinary argv and pass to the handler unchanged; there is no rewrite step to "preserve" them through. `SKIM_PASSTHROUGH=1` is the escape hatch. The wrapper surface reads no skim flag from argv; `SKIM_PASSTHROUGH=1` and `SKIM_DEBUG=1` are the only controls there. Wrapper install/uninstall only ever touches symlinks whose target stem is `skim`/`rskim` — never regular files.

3. **Post-run output compression (the after-run hook)** — the same hook script and the same `skim rewrite --hook` argv as the rewrite engine, but routed on `hook_event_name == "PostToolUse"` in `cmd/rewrite/hook.rs` `route_stdin`, for Claude Code in auto permission mode only (any other agent, mode, tool or event gets no output). The command has already run, so skim never runs anything on this path: `cmd/rewrite/post_hook.rs` `run_post_hook` spawns no process, opens no file, writes no analytics row, force-raw marker or sidecar, and never returns a permission decision. For an allow-listed command (`cat` of exactly one code file, `cargo test`, `pytest`, and the lint tools in `POST_COMPRESS_RULES`) it replaces `tool_response.stdout` with a compressed view of the captured text and adds one `[skim]` line to `stderr`: `[skim] compressed view of '<tool>': parsed summary, <raw> B → <served> B — SKIM_PASSTHROUGH=1 for full output` for a parser, or the `lossy_view_marker` text for `cat`. The ADR-001 net-savings guard prices that marker line, so a view that does not save bytes is not served. Failed runs (`PostToolUseFailure` has no replacement slot), captured stdout of 29,000 characters or more (`MAX_STDOUT_CHARS`; at about 30,000 Claude Code keeps the raw text in a file and gives the hook only a prefix), background runs, compound commands, pipes, redirects (including `2>&1`) and env-prefixed commands stay raw. It shares the command gates (`command_gates`) with the rewrite engine, but not its text-transformation guarantees: there is no rewrite, so flag preservation and corruption-bail do not apply. `skim init` writes both event keys (`hook_event_keys()`); `skim doctor` notes a missing `PostToolUse` entry without failing.

**Which surface decides what (stdout destination).** Each surface can observe something the other structurally cannot, so neither is authoritative alone:

- **`fstat` is ground truth, and wins wherever it can see.** It knows a regular file / char device / socket after the shell has already wired fd 1 up, when no redirect token remains in argv. `isatty(1)` — not `FileType::is_char_device()` — is what identifies a terminal; using the file-type bit as an `isatty` proxy misclassifies `/dev/null`, `/dev/zero` and `/dev/random` as terminals and compresses into them.
- **A pipe is ambiguous at the fd level**, and this is the one gap `fstat` cannot close: `| cat` (compress — skim's core value) and `| tee out.txt` / `$(…)` (compress = data loss) are the same FIFO. Only the rewrite engine sees pipeline *shape*. It records its verdict via `command_needs_exact_bytes` (`cmd/rewrite/compound.rs`) in a force-raw sidecar marker, which the wrapper discovers by ancestry walk (`session_sidecar::read_force_raw`). **Its `BYTE_EXACT_PIPE_CONSUMERS` denylist covers three categories, not two:** consumers that *persist* the bytes (`tee`, `dd`, `split`, `nc`, the archivers), consumers that *digest* them (`sha256sum`, `b2sum`, `crc32`), and — third — consumers that **measure, compare or render** them, where the reader's question is about the bytes themselves so a substituted stream answers a different question than the one asked. `wc` was the live defect: producer held at `git log -n 40` (raw 115052 B / 2192 lines), `wc -l` returned **40** and `wc -c` **4118**, exit 0, zero stderr, no marker; `cmp` and `diff` on genuinely-different inputs flipped **exit 1 → exit 0**, a silent false "identical" — the failure mode no reader would predict from the word "compression". **The discriminator is falsifiability**, which is why `nl` is deliberately absent: `nl` prints its number beside the content it counted, so a substituted stream shows numbering that visibly belongs to the wrong bytes — grouping it with `cat -n`/`head`/`grep -n` as a renderer — while `wc` emits only the number, so a wrong count is unfalsifiable; `test_needs_exact_bytes_nl_renders_and_still_compresses` pins that exclusion against a later "complete the set" edit. **Structural limit:** membership is keyed on the consumer's command head name alone (`segment_head`), so a flag-discriminated consumer is unrepresentable — `head -c 100` measures exact bytes and `cat -n` renders them, but neither can be listed without also denying bare `| head` and `| cat`, the two pipelines skim exists to compress; those shapes stay compressed knowingly, and closing them needs a per-flag key, not a new name. **Surface reach: the denylist arms only the PATH-wrapper surface.** `force_raw_requested` is consulted at exactly one call site — `main.rs:1049`, inside the `detect_argv0_dispatch()` branch — whose comment records that the Subcommand and FileOperation branches are intentionally NOT guarded, because hoisting the guard above `detect_argv0_dispatch()` would break explicit `skim … > out.txt` invocations. So it changes nothing on the hook surface, which already bails on every pipeline but bare `| cat`, and nothing on the explicit surface: `skim git log -n 40 | wc -l` still returns 40 **by design** — typing `skim` yourself is the opt-in to the compressed view, the same rationale as the un-`fstat`-gated explicit-subcommand path in the next bullet. The marker is set *or cleared* by every hook invocation that reaches command extraction, so it never outlives a command the hook actually processed; five early exits (passthrough mode, AwarenessOnly agents, stdin read error, JSON parse error, missing command field) skip the write, and a marker left behind by one of them lives until the next processed command or the 300 s reap; the 5 s hook watchdog's `process::exit(0)` can also pre-empt the write. **The key is `{ppid}.{tool}.raw` — PID *and* tool name.** PPID alone is not a command identity: every command an agent runs shares that PID, so a PPID-only key made one command's verdict decide unrelated concurrent, background, and nested-sub-agent wrapper invocations (and let their clears delete a live marker). The tool component comes from `command_heads`, the command heads the hook saw; a shape that defeats head extraction (`$(…)`, backticks, process substitution) falls back to the wildcard `{ppid}.raw`, which matches every tool. Additionally, `pipe_consumer_needs_exact_bytes` returns `true` for `Bail`-split commands that contain a `|` — a conservative fallback that marks complex pipeline shapes (heredocs, subshells, backticks enclosing a pipe) as needing exact bytes rather than silently passing them through compression. **Accepted limitations:** the marker exists only when the hook fires — a bare wrapper invocation with no PreToolUse hook gets `fstat`-only behaviour; and two *same-tool* commands under one agent still share a key, so a concurrent `git status` can clear a live `git log | tee f` marker. Both fail toward compression, and for a FIFO wired to a byte-exact consumer (`| tee f`, `| sha256sum`) that is byte loss, not a lossless fallback: measured 304 bytes written instead of 6803, silently. The same-tool clear is a narrowed remnant of the pre-marker behaviour; the hook-less case is pinned by `no_hook_means_fstat_only_behaviour`. A third accepted limitation — PID reuse — occurs when a PID is recycled within the 300 s `FORCE_RAW_MAX_AGE` window: a new process finds the prior process's stale marker and serves raw instead of compressing. Unlike the same-tool key collision and the hook-less case, PID reuse fails toward lossless compression (extra raw bytes, none lost).
- **The rewrite engine's text scan is a hint, not an authority.** `stdout_redirected_to_file` tracks fd state left-to-right so `cmd 2>f >&2` (stderr to a file, then fd 1 dup'd from it) is recognised as a stdout→file redirect. The explicit-subcommand path (`skim git log > out.txt`) is deliberately NOT `fstat`-gated: the user typed `skim` there, and that path cannot tell a user-authored `skim …` from a hook-injected one.

**Testing / verification implication:** the surfaces share the per-tool *handlers* (output compression) but NOT the dispatch front-end. A test that drives the `--hook`/`rewrite` path does **not** exercise the wrapper path, and vice-versa. A test that drives a `PostToolUse` input exercises neither of the other two. When verifying behavior — and when confirming Snyk/CI actually cover a change — identify *which* surface a test hits and cover both where the behavior could diverge. The rewrite *text-transformation* guarantees (flag preservation, text-scan corruption-bail, pipe-source passthrough via `is_bare_cat_pipeline`) are rewrite-engine-only and do not apply to the wrapper surface. The stdout-destination guarantee, however, exists on *both* surfaces via distinct mechanisms: the rewrite engine uses `stdout_redirected_to_file` / `command_needs_exact_bytes` (a text scan before exec); the wrapper uses `stdout_should_serve_raw` (`fstat` + `isatty` on fd 1 after the shell has already redirected) plus the force-raw marker. Do not conclude that wrappers have no output-fidelity protection (#370). The helpers `arg_matches_flag` and `args_before_separator` are shared across both surfaces (D3/D4/D5 in the wrapper gate and the rewrite-engine flag checks both import them from the same module), so flag-matching semantics — including the `--` separator cut-off — are identical on both paths. The full 9-destination × 2-surface matrix is pinned in `crates/rskim/tests/cli_stdout_destination.rs`.

## Environment Variables

- `SKIM_PASSTHROUGH=1` (or `--passthrough` CLI flag) — bypass compression and exec the real tool with raw argv, at the structural convergence gate in `cmd/dispatch.rs` — the `is_passthrough_mode()` gate, conjoined with `is_meta_subcommand`, the `env` exclusion and `handler_reads_stdin`. **It is not universal — see the two exceptions below; "bypasses all compression" is the intent, not the measured behaviour.** The `--passthrough` flag strips skim-only flags from the forwarded argv so the real tool never sees flags it does not understand. Stripped for all tools: `--show-stats`, `--passthrough`, `--debug` (only when the tool does not own that flag), `--max-lines N`/`=N`, `--tokens N`/`=N`, `--last-lines N`/`=N`, `--line-numbers` (long form only; `-n` is not stripped). Additionally stripped for `git` only: bare `--json` and `--mode`/`--mode=<val>`. Nothing is stripped after a bare `--` end-of-options separator. Exception 1 — `env`/`printenv`: `SKIM_PASSTHROUGH=1` does not bypass credential redaction, and the control is **two independent layers plus a third, separately-scoped gate** (PF-012, defense in depth) — flattening them into one function is how an audit concludes the control is gone. (a) The **convergence gate** excludes `env` by **literal name** (`subcommand != "env"`), so that one command never reaches the hatch at all. (b) The **per-handler `never_passthrough: true`** flag on `cmd/file/env.rs`'s `CONFIG` — which both `skim env` and `skim printenv` route to — is the execution-layer refusal (`cmd/execution.rs`: `let passthrough = is_passthrough_mode() && !never_passthrough`), reached whenever the convergence gate declined. (c) `redaction_is_mandatory` (matching `env` **and** `printenv`) is the **structural** gate, and it guards NEITHER of the two above: its own rustdoc names its consumers as the *other* raw-serve paths — `main.rs` D2b (`stdout_should_serve_raw` / `force_raw_requested` → `run_inherited_passthrough`) and `dispatch_inner` D4 (the skip-flag gate that would otherwise let `env -u HOME` dump the whole environment). So do not go looking for passthrough coupling inside `redaction_is_mandatory`; there is none, by design, and its absence is not evidence the hatch is unguarded. **Asymmetry worth knowing before you rely on it:** `printenv` is named by (b) and (c) but NOT by (a)'s literal, so under `SKIM_PASSTHROUGH=1` it depends on the convergence gate declining — i.e. on `handler_reads_stdin` being true, which for a bare `skim printenv` off a TTY it is — to reach the handler that redacts. Source-read, not measured; measure before treating `printenv` and `env` as equivalent on this path. **Exception 2 — the multi-level dispatchers (`cargo`, `dotnet`, `go`, `swift`), off a TTY**: the gate declines whenever `handler_reads_stdin` is true, and `handler_visible_args` strips a leading non-flag token for those four tools, so `skim cargo check` reduces to an EMPTY arg slice and `should_read_stdin` (`!stdin.is_terminal() && no_real_args`) returns true — in every agent harness, CI job and pipeline, i.e. exactly where the escape hatch is reached for. The command then falls through to the compressed handler, and the build family has no `SKIM_PASSTHROUGH` branch of its own: `cmd/build/mod.rs::run_parsed_command` always spawns the tool, but it does **not** always summarise — it has three arms and two of them serve raw. It summarises only on the ADR-001 guard's `Keep` arm; the guard's `Passthrough` arm and the already-`passthrough` tier-3 arm both emit the child's bytes verbatim. So `SKIM_PASSTHROUGH=1 skim cargo check` returns the compressed summary **when the guard elects `Keep`**, never because the hatch was honoured, and serves raw otherwise. Bare `skim cargo build` was measured returning **0 bytes on stdout** — re-measure per descriptor rather than quoting that figure, because `1993063` (*fix(build): preserve the child exit code and keep stderr on fd 2*) has since moved the child's diagnostics off fd 1. Interactively the same command works, because a terminal stdin makes `should_read_stdin` false and the gate fires. To get raw bytes out of a build tool off a TTY, run the tool directly rather than through `skim`. **Both build-family raw arms now write through `emit_raw_passthrough_split`**, which is byte-faithful by construction and so diverges from the pre-split emission in two user-visible ways — neither is an oversight and neither should be "restored": child diagnostics **stay on fd 2** instead of being merged onto fd 1 (so `skim cargo fmt --check > out.txt` captures less than it did, and `2> err.txt` captures more), and **no trailing newline is appended** on either arm, so a child whose output does not end in `\n` is forwarded without one. **PF-024 is not retired by the `gh` fix** — it is closed for `gh` and open for the whole build family: `cargo.rs` injects `--message-format=json` whenever the user supplied none, and both the ADR-001 guard baseline and the raw arm then serve that injected NDJSON to someone who typed `skim cargo build`, so the guard's "did I help?" question is asked against a command the user never ran. Neither `raw_override` nor `RawFallback` appears anywhere under `cmd/build/`. Indefinite commands (`vite dev`, `jest --watch`, bare `skim vitest`) auto-pass-through live; use `skim vitest run` for a compressed one-shot.
- `SKIM_DEBUG=1` (or `--debug`) — enables raw-fallback diagnostic banners on stderr for no-loss raw-fallback paths (see **Stderr notice taxonomy** in Design Constraints below; loss-bearing elision markers and the ADR-008 transparency marker are unconditional and not gated by this variable). In hook mode the startup provenance line goes to `hook.log`, never stderr (GRANITE #361 Bug 3); drift events are also logged to `hook.log` unconditionally — `skim doctor` is the primary on-demand diagnosis path.
- `SKIM_SESSION_ID` — analytics session attribution; priority sidecar > env > `--session-id` flag (flag is a forward-compat fallback only — the hook no longer injects it). Set it alongside the PATH export so sub-agents inherit it.
- `SKIM_CACHE_DIR` — relocates **all** skim cache state: parser cache (`.json` files),
  tee output (`tee/`), and the **default** `analytics.db` location. A usable value **is**
  the cache root and is used as-is (no `skim` suffix is appended by the resolver);
  the platform path is only the fallback arm. `cache.rs::cache_root_from` treats
  an empty value as unset, and also a **whitespace-only** one — but only when the path is
  valid UTF-8. A **non-UTF-8** `OsStr` path is deliberately never trimmed and never
  rejected: it is a valid filesystem path and is used unchanged. Only when the value is
  unset by those rules does it fall back to `dirs::cache_dir()/skim` — `~/Library/Caches/skim`
  on macOS, `~/.cache/skim` on Linux. **Caveat:** pre-existing analytics history at the
  old default `analytics.db` is **not migrated** — setting this variable for the
  first time causes `skim stats` to start from an empty DB at the new location; move
  the old file manually if you want to preserve history.
- `SKIM_ANALYTICS_DB` — overrides the analytics DB path directly; **takes precedence over
  `SKIM_CACHE_DIR`** for the DB location. When `SKIM_ANALYTICS_DB` is set, the DB is
  opened at that exact path regardless of `SKIM_CACHE_DIR`. To isolate all skim state
  in a sandbox it is sufficient to set `SKIM_CACHE_DIR` alone (the default analytics.db
  moves with it).
- `SKIM_DISABLE_ANALYTICS=1` — disable recording. `SKIM_INPUT_COST_PER_MTOK` — $/MTok for cost estimates (default 3.0).
- `SKIM_WRAPPERS_DIR` — overrides the `~/.skim/bin/` wrapper symlink directory used by `skim init --wrappers` and `skim init --uninstall`. Primarily used in tests via `skim_sandboxed()` to redirect wrapper installation into a TempDir sandbox so real `~/.skim/bin/` is not touched. An empty value is treated as unset (falls back to `~/.skim/bin`).
- `SKIM_DEPTH` / `SKIM_WRAPPER_PARENT` — set by skim itself, not user controls. `SKIM_DEPTH` counts nested skim starts on every surface; above 32 skim exits 126 with one stderr line. `SKIM_WRAPPER_PARENT` (`<tool>:<pid>`) makes a wrapper that a wrapper of the same tool started exit 126. Tests remove both from the sandbox (`SANDBOX_REMOVED_VARS`).
- Session-provider overrides for `discover`/`learn`/`agents`: `SKIM_PROJECTS_DIR`, `SKIM_CODEX_SESSIONS_DIR`, `SKIM_COPILOT_DIR`, `SKIM_CURSOR_DB_PATH`, `SKIM_GEMINI_DIR`, `SKIM_CRUSH_DIR`.
- **Agent config-dir overrides** (read by `skim init` / `init --uninstall` / `doctor` — these are the agents' *own* variable names, not `SKIM_`-prefixed): `CLAUDE_CONFIG_DIR`, `CURSOR_CONFIG_DIR`, `GEMINI_CONFIG_DIR`, `COPILOT_CONFIG_DIR`, `CODEX_CONFIG_DIR`, `CODEX_HOME`, `CRUSH_CONFIG_DIR`. Each redirects that agent's hook script, settings file, permissions sidecar, and guidance file (`GEMINI.md`, `copilot-instructions.md`, …) away from the `~/.<agent>/` default. **Two resolvers, and Codex is the one place they read DIFFERENT variables** — do not treat the list as one namespace: `DetectionEnv::from_process` (`cmd/init/flags.rs`) reads `CLAUDE_CONFIG_DIR`, `CURSOR_CONFIG_DIR`, `GEMINI_CONFIG_DIR`, `COPILOT_CONFIG_DIR`, **`CODEX_CONFIG_DIR`** and `CRUSH_CONFIG_DIR`, and governs the hook script, settings, permissions sidecar and agent detection — i.e. everything install and uninstall touch; `InstructionEnv::from_process` (`cmd/session/types.rs`) reads `CLAUDE_CONFIG_DIR`, **`CODEX_HOME`**, `CRUSH_CONFIG_DIR`, `GEMINI_CONFIG_DIR` and `COPILOT_CONFIG_DIR`, and governs the guidance file only. **It has no Cursor entry, and neither resolver redirects Cursor's guidance file — `CURSOR_CONFIG_DIR` does not reach it at all.** `inject_guidance` → `resolve_instruction_path` → `AgentKind::instruction_file` returns a **cwd-relative** `.cursor/rules/skim.mdc` for project scope and `None` for global (Cursor has no file-based global config; pinned by `test_instruction_file_cursor_global_unsupported` in `cmd/session/types.rs`). So **sandboxing Cursor's `.mdc` means controlling the process's cwd, not an env var** — no combination of the variables in this list will keep it out of the directory a test happens to run in. (`rules_dir()` is a different thing: it is used by `cmd/learn.rs` for the corrections file, never by init.) So for Codex, `CODEX_HOME` alone redirects the guidance file and leaves install/uninstall pointed at the real `~/.codex`; `SANDBOX_REDIRECTED_VARS` in `tests/common/mod.rs` sets both, to the same path, for that reason. Do not confuse any of these with the `SKIM_GEMINI_DIR` / `SKIM_COPILOT_DIR` session-provider overrides above, which point at transcript directories and have no effect on install/uninstall. Any test that shells out to `skim init`/`--uninstall`/`doctor` must set them (use `common::skim_sandboxed`) or it will mutate the developer's real home directory. **Environment is only one of the two sandbox axes**, and setting every variable in this list still does not confine a test: `skim init` resolves a project root by walking ancestors of the process working directory, which no variable here can redirect — that is how real `.git/hooks` entries were getting written into this clone. `skim_sandboxed_with_bin` pins the cwd axis as well; use it rather than assembling the env by hand.

## Design Constraints

**MUST:** stream to stdout (never write intermediate files) · prefer `&str` slices over allocation in the hot path · tolerate incomplete code (rely on tree-sitter error nodes) · stay under 50ms for 1000-line files (benchmark regressions block) · fail loud with actionable messages, never silently · modes via CLI flags only, no `.skimrc` · **compress, never truncate** (#317): wrappers may re-encode output but never show less than the raw tool; an unavoidable safety bound must use `output::elision_marker` (exact counts + `SKIM_PASSTHROUGH=1` hint); unexpected non-zero exits forward raw output instead of compressing; rewrites must reconstruct the command byte-faithfully or bail (never emit a command that errors or changes semantics). **git diff enhancement view must fit within the raw budget** — any enriched render (e.g. hunk-scoped AST breadcrumbs) is guarded by an ADR-001 net-savings check; if enrichment expands the output beyond the raw diff size, raw is emitted instead (git-diff raw-budget decision reversal: the unguarded enhancement view was replaced by a guardrail-protected one). A breadcrumb line in that view is prefixed `~` — a fourth line prefix beside git's `+`, `-` and space, marking a declaration header skim pulled in from outside the hunk rather than a line git printed; it is a one-character substitution on a line emitted either way, so it costs zero net bytes, and no per-diff legend is emitted because ADR-003 already records this view at 2-5x raw on large diffs (the same budget that makes `write_hunk_boundary` withhold its `@@` line on single-hunk files, ≤29 B per hunk otherwise). That git-diff guard is the ADR-001 check in its **uncharged** form; the charged form — where a class-1 stderr disclosure is priced into the same verdict — lives on the file-transform path and is described under **Stderr notice taxonomy** below.

**Stderr notice taxonomy (ADR-011):** Every new `stderr` notice must be classified before it is added — (1) **loss-bearing markers** (elision markers with exact counts + `SKIM_PASSTHROUGH=1` hint; ADR-008 lossy-view transparency marker) fire when the reader sees less/different from raw and are **unconditional**; (2) **no-loss raw-fallback banners** (guardrail chose raw, unexpected exit, tool killed) fire only on lossless paths and are **gated behind `SKIM_DEBUG`/`--debug`** (`crate::debug_log!` / `io::sink()`). If a notice can fire when the reader sees less/different from raw, it is a marker (always on); if it fires only on a lossless raw fallback, it is a banner (debug-gated). Do not re-conflate the two classes. (3) **On the file-transform path a class-1 marker is CHARGED against the ADR-001 net-savings decision**, so a marker is an *input* to view selection and not only an output of it — it can tip the verdict to raw and thereby suppress itself. `output/fidelity.rs::decide_with_notice` prices the notice against the compressed side as a **differential**, `overhead = cost(notice if Keep) − cost(notice if Passthrough)`, which is `None` wherever the raw branch would print a byte-identical notice of its own; charging the absolute cost there double-counts (#519) and pushes the guard toward raw on exactly the paths where raw is also disclosed. Only `process.rs` routes through the charging entry point (`guardrail::apply_to_stderr_with_notice`); **`cmd/git/show.rs` and `cmd/git/diff/mod.rs` still call the uncharged `apply_to_stderr` shim**, and `cmd/build/mod.rs`'s `Keep` arm passes `None` deliberately (its stdout accounting still carries the success-line hole the ADR-011 census recorded, and a stderr-only charge would make a partial accounting read as a complete one — charge both together or neither). `decide` / `apply` remain charge-nothing shims on purpose, so a call site that has no notice, or has not been audited for one, cannot charge the wrong thing by omission.

**MUST NOT:** add syntax highlighting (use `bat`), linting (use linters), type checking (use `tsc`/`mypy`), or LSP features — all out of scope.

**Targets:** parse+transform <50ms/1000 lines · 60–80% token reduction (structure mode) · <10ms startup · <1s for 100 files (parallel via rayon).

**Exit codes (skim's own):** `0` success · `1` general error · `2` parse error · `3` unsupported language. **Wrapped build tools forward the child's code**, so that set is NOT exhaustive for them and `$?`-keying CI scripts must read the wrapped tool's code, not this list. `cmd/build/mod.rs::resolve_exit_code` returns `max(child, derived)` — the child's status narrowed by `exit_code_from_status`, raised (and deliberately never lowered) by the parser's own failure verdict, so a gradle `BUILD FAILED` on a zero exit still fails. `skim cargo check` therefore exits cargo's `101`, and `skim make` with no makefile exits make's `2`, colliding with skim's own parse-error code. `exit_code_from_status` is fail-closed: a signal kill (`None`) and any out-of-range or negative child status (Windows NTSTATUS — `STATUS_ACCESS_VIOLATION` arrives as `-1073741819`) report **1**, never `0`, and a status above 255 saturates to 255 rather than wrapping a `256` back to `0` through a bare `as u8`. `clamp(1, 255)` rather than `clamp(0, 255)` is the whole mechanism.

**`skim search` is an exception to that list:** `0` a line matched (or, in the word view, a file holds a word) · `1` no match · `2` a usage error (unknown or removed flag, bad value, empty pattern, a second pattern, a flag conflict, unknown `-t` type), an invalid regex (including the size limit), a bad `--root` (or cwd `/` without `--root`), or a git index or repository state that cannot be read · `141` on unix when the reader of stdout stops (`pipe_closed_exit`; `0` elsewhere). Exit 2 writes `skim search: …` to stderr; with `--json` it also prints `{"error":"…"}` on stdout, otherwise stdout is empty.

## Adding a Language

**tree-sitter language:** add the `tree-sitter-<lang>` dep at the workspace version, then add an arm to each of these **exhaustive, wildcard-free** tables — the compiler rejects an omission at build time:
1. `to_tree_sitter()` (`rskim-core/src/types.rs`) — maps the variant to its grammar
2. `literal_syntax()` (`transform/literal_scan.rs`) — string/comment delimiter rules; verify the node-kind names used against the grammar's `node-types.json` at the pinned version
3. `literal_fragment_kinds()` (`transform/literals.rs`) — inner-text node kinds; same grammar-verification step required
4. `get_comment_prefix()` (`transform/utils.rs`) — single-line comment prefix

~60 min, accounting for the grammar-verification step.

**Data format (non-tree-sitter, like JSON/YAML/TOML):**
1. Add a `Language` variant in `rskim-core/src/types.rs`; return `None` from `to_tree_sitter()` and from the `get_*_node_types()` functions.
2. Implement a transform module (`src/transform/<fmt>.rs`) with security limits (max depth, max keys).
3. Route it in `Language::transform_source()` (Strategy Pattern).
4. Add the variant to `LanguageArg` in `crates/rskim/src/main.rs`.

## Testing

Fixtures live in `tests/fixtures/<language>/`, ≥4 per language. Integration targets: ≥95% parse success on real-world code, output still parses, 60–80% token reduction.

**Known edge cases:** incomplete code → tree-sitter error nodes · files >100MB → error (memmap is future work) · binary files → detect and reject · stdin supported (`cat file.ts | skim`).

## Release

Run `./scripts/release-prep.sh <version>` (pre-flight checks + mechanical version bumps). You still create the `release/vX.Y.Z` branch and write the CHANGELOG entry by hand. Seven crates publish to crates.io and all carry the same version: `rskim-core`, `rskim-contract`, `rskim-llm`, `rskim-tokens`, `rskim-compress`, `rskim-proxy` and `rskim`. The version lives in the `version` line of each of their `Cargo.toml` files, in every versioned `rskim-*` dependency line, and in the README status line; `release-prep.sh` bumps all of them and stops before any edit if one has drifted. The build job checks `crates/rskim/Cargo.toml` against the tag, and the crates.io job checks all seven before the first publish. Pushing tag `vX.Y.Z` triggers `.github/workflows/release.yml`: test → build (7 targets) → GitHub Release → crates.io (`rskim-core`, `rskim-contract`, `rskim-llm`, `rskim-tokens`, `rskim-compress`, `rskim-proxy`, then `rskim` — each after the crates it depends on) → npm → Homebrew tap.
